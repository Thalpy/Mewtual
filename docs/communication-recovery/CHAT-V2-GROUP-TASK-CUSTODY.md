## Actual source and owning API

Only the paid `GenesisSourceDataRef` enters the first constructor. It borrows the same real
opened SourceSaved data, immutable closed SDK seed and supporting resource holders; it is not
constructed from a profile label, raw snapshot, status or caller trait. Source ID/full context,
the original read identity and original SDK-seed identity are captured before writers. Every
later source check repeats those exact original observations and cheap negatives.

The agreed Store-private shape is:

```text
V2CurrentLayoutStore::prepare_genesis_group_namespace(&GenesisSourceDataRef)
    -> Result<PreparedV2GenesisGroupNamespace, AppError>
task.retry_directory(&mut self, &ServerStore, &GenesisSourceDataRef) -> Result<(), AppError>
task.saved_directory() -> Result<&Arc<SavedV2GroupDirectory>, AppError>
task.observe_original() -> OriginalV2GenesisGroupObservation
task.retains_original(&ServerStore, &GenesisSourceDataRef) -> Result<(), AppError>
observation.require_same_original(&task) -> Result<(), AppError>
```

The task owns no Store, key, transport or vault-session loan. An old task cannot adopt a newly
opened Store or a byte-equal new paid read/SDK seed. Observation checks take no locks, I/O,
SDK entry, pool operations or encoded copies. The actual source authorities remain the audited
closed negative implementations; no arbitrary positive callback is added.

## Persistent negative ownership

The actual pins Runtime contains an optional, separately prepaid fixed sixteen-slot buffer.
Default/old mounts allocate no buffer. Preparation acquires its real shared-pool debit and
builds it outside all host writers. Each installed slot has an independent retained metadata
payment, a fixed bounded group/vault/root/mount/source binding, a weak tiny original TaskLife,
and the original inert directory-output custody. Only the non-Clone task owns strong TaskLife;
its Drop cancels immediately. Expired/cancelled life never evicts a slot or means absence.

Directory-output custody contains only fixed path, held File/session identity and closed
progress DATA. It owns no source graph, key, Store, session or positive sender. The same cell
is retained by Store and task before any filesystem effect, so partial or saved output survives
caller Drop. It retains its actual custody payment LAST, so a surviving inert Entry still pays
for those paths/Files. It stores saved outcome DATA, never an Arc back to SavedV2GroupDirectory.
No mutex/callback can obtain fresh source or permission from this cell.

Register under the actual vacant admission writer, then pins, canonical namespace and archive
Root. Before installing, reject any-signer retained JOIN current/admitted expected-or-next
source, any same-group admission row/owner, old group pin, unknown canonical association,
old matching canonical file/stage or RAM owner, previous group registry entry, and any fixed
group-path presence. Recheck the actual source/mount/layout after every subordinate wait.
Buffer/entry transfer is the final infallible move; a refusal leaves all prepared ownership
outside the locks. No error after registration may silently lose the task or its inert debt.

## Explicit first-source and first-handle limits

The approved V2 source factory accepts only its original actual `Server::found`/fresh SDK
group creation; it accepts no caller-selected GroupId, restored server or decoded Fresh
substitute. Group uniqueness between two independent approved sources therefore relies on
the SDK's cryptographic fresh-GroupId assumption. The current five-slot unresolved-source
registries are not a complete authenticated cold source-by-group index. Do not describe the
old filename index or a partial source-target walk as such an index. Any future source-adoption
or migration producer must close that boundary explicitly before using this first-genesis path.
Actual same-group legacy rows/owners and bounded live pre-row predecessor conflicts remain
negative exclusions regardless of that factory assumption.

The directory writer records `CreatedWithoutHandle` immediately after successful mkdir, with
the output lock already held. A failure before its first directory File is captured preserves
that state, directory and inert fees, and refuses path-only warm/cold adoption. Once a File is
captured, it is retained before session-id queries/sync and can retry only that same object.
The first-handle capture relies on cooperative app writers/private live directory, not an
atomic capability against a hostile concurrent file manager. Unknown first-handle/cold partial
closure remains a separate availability gate; neither state can become Saved or Current.
Final Source/ID3/account waits precede the last held/named group-directory proof and cached
negative comparison. The saved receipt's proof-only Init1 role is distinct from the writer-bearing
Head role: `lock_archive_root()` validates retained Head DATA, while
`lock_archive_root_for_writer(same_registration)` alone supplies Root's Head writer type.
