# Original fresh-founder driver (13 November; authored, CI pending)

This is a closed Root library producer on one existing typed vault mount. It
does not install a native row, authenticate a native command, support cold
operational reopen, implement joined-member authoring or enable Chat V2.

`V2CurrentLayoutStore::prepare_fresh_v2_text_founder` requires the actual archive,
JOIN execution, Current and member-outbox handlers before creation. The existing
vault/open checks stay intact. Its checked local policy rejects a seed budget
that cannot decode the founder's declared grammar before any invocation or SDK
work. An existing invocation returns the caller's untouched runtime inputs; it
cannot adopt a stored source as a fresh runtime.

`PreparedFreshV2TextFounder` owns the original Creation -> Planning -> SourceSaved
-> warm runtime -> paid source read/SDK restoration -> Current -> settled genesis
-> empty operational promotion chain. Each completed stage is cached before a
late check. A refused consuming transition restores the same inputs. Persistent
source allowance, ciphertext, nonce and identity are never reset by retry. The
original SDK drains outside all writers before the saved source's separate paid
SDK restoration. The actual creator and its fees stay in the final product.
There is no raw Store, Host, Server or SDK extractor.

The product's borrowed historical binding identifies its library binding version,
actual vault/layout, bounded group, full signer, SourceSaved identity, Profile
and original pin-ciphertext identity. These are DATA, never a row or owner issuer.
No native backend-row codec is introduced. Readiness is advisory; every later
member operation still performs the existing actual Current/source checks.

## Original-to-Current reservation bridge

The founder's original reservation and the new Current row have distinct
identities. Copying labels or using the cold-runtime constructor would not prove
their relationship. `CompletedWarmFounderOrigin` is instead captured privately
after the real SavedTerminal, source registration, exact paid-read identity and
source/context checks. The genuine runtime parts and this origin are cached
together before late negatives.

After actual Current2 storage, its original head/task/writer/source proofs run
before and after bridge allocation. The reservation-only adapter keeps the old
identity for Sync's unchanged attachment pointer check and separately retains
the real Current identity for validation. It composes BOTH complete cancellation
values and both weak revokers. Replacing a cancellation authority never discards
the previous Current authority: the composite owns the full old and Current
observers. The adapter cannot act as a Current/publication binding or writer.
Every cached association must still match the exact successor; labels alone
cannot rebind it. All host guards drain before SDK scope attachment. Final Node
and selected-head proofs remain mandatory.

The existing Sync source and key-cut checks are unchanged. The installed node's
scope now observes both reservations, so either revocation closes the same
attachment. The original predecessor slot was already removed after genuine
saved founding intent without revoking the creator; Current1/2 do not require
an exception for revoked originals.

The driver prepays its phase/Box/return layouts, runtime and warm-refusal
allocations, bridge controls and bounded context copies. Original creator,
source, source-read, SDK and Current payments remain independent. No pool,
resource cap, stack or execution allowance is increased.

## Evidence and remaining work

The earlier one-mount SourceSaved prerequisite passed on Linux and Windows at
`741156cc` in [run43328380312](https://github.com/Thalpy/Mewtual/actions/runs/43328380312).
That result predates this driver and proves neither warm pairing nor native use.

New regressions (not executed yet) cover four early handler/payment/foreign-mount/
budget cases on both operating systems. Four Windows cases exercise the real
whole warm factory and durable member save/retry, independent old/Current
revocation through the installed node's source predicate, and refusal of a
corrupted cached successor identity after a genuine positive control. Native
custody in the Root save case is explicitly a test box, not authentication.
The focused lane requires exact nonempty counts (one mount prerequisite plus
four or eight driver cases), and rejects missing/duplicated/changed cohorts.

Actual-diff design review found and corrected the warm identity mismatch and
incompatible-budget failure. Static formatting, ambient/raw-filesystem gates
and no-Cargo harness self-checks pass. Driver compilation/execution, all complete
suites, workspace-wide strict Clippy and audit remain required. Final actual-diff
re-review found no remaining findings in this slice; no runtime success is
inferred from static review.

The paired native backend/registry, original command credential and key-cut
admission, exact generation/lock ordering and durable backend binding are still
required. Cold operational ownership must be implemented before activation or
restart claims. Joined sources, governing archive/transport, later-prefix and
combined acceptance remain separate required consumers. See
[the native prerequisites](CHAT-V2-NATIVE-MEMBER-SAVE-NEXT.md).
