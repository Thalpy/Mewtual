# TLS dependency correction (20 October 2026)

The refreshed root audit found RUSTSEC-2026-0382 in rustls-webpki 0.103.15 and
RUSTSEC-2026-0381 in webpki-roots 1.0.9 plus its 0.26.11 compatibility shim. Both root and
native lockfiles now resolve rustls-webpki 0.103.16 and webpki-roots 1.0.10. The native DER
bundle webpki-root-certs is also updated to 1.0.10 for RUSTSEC-2026-0383. No dependency
requirement, feature, source, licence or application authentication path changed.

The upstream [verifier correction](https://github.com/rustls/webpki/pull/546) rejects the
distrusted public keys; the [trust-root update](https://github.com/rustls/webpki-roots/pull/133)
removes the affected root. The resolved verifier calls the explicit distrust check during
certificate-path verification. This changes TLS certificate acceptance, rather than MLS,
Noise identity, voice envelopes or application permissions.

The advisory also matches webpki-roots 0.26.11's version. Inspection of that exact registry
artifact shows it contains no root bundle: its only exported root constant is
`pub use parent::TLS_SERVER_ROOTS`, and parent is webpki-roots ^1. Both locks now point that
edge to 1.0.10. The 0.26.11 shim remains required by libp2p-websocket 0.45.1.

The exception in deny.toml is paired with mandatory version bans, using the
[cargo-deny bans contract](https://embarkstudios.github.io/cargo-deny/checks/bans/cfg.html).
They allow only the reviewed 0.26.11 shim or fixed bundles >=1.0.10. A vulnerable concrete
bundle appears as its own graph package and fails the bans even though the advisory ID
is ignored. Other pre-fix stable shim versions also fail. Ordinary semver ranges exclude
prereleases, so a third ban explicitly covers the published 0.26.0-alpha.0/.1/.2 family.
Review this exception if upstream introduces another prerelease release tuple; these ranges
are not a claim to fence arbitrary future prereleases. Remove this exception when the parent
dependency no longer needs the shim or the upstream advisory accounts for it.

Do not copy the exception without its bans. In particular, updating only the verifier does
not fix the roots audit, and an unconditional advisory ignore without downgrade enforcement
would conceal vulnerable root bundles. The separate experimental IPC dependency audit and
its earlier Tauri/quick-xml/plist findings are not cleared by these updates.

The root audit passes (`target/voice-hello-root-deny-final-2.log`). A metadata-only fixture
pinning the vulnerable 1.0.9 bundle is explicitly rejected by bans, with the expected exit2
and exact package finding (`target/voice-hello-tls-downgrade-final.log`). The fixture never
compiles and does not modify either application lockfile. Initial invocations used the wrong
config-flag position and then expected the advisory exit code instead of the bans exit code;
only the final verified invocation is accepted evidence.

Read-only review then found the prerelease matching gap described above. A second metadata-only
fixture pins 0.26.0-alpha.2 and fails with the expected bans exit2 and exact package finding
(`target/voice-hello-tls-prerelease-final.log`). The final root audit passes with all three bans.
The review correction changes no lockfile or runtime code.

The separate full native audit still fails on h2, proc-macro-error, quick-xml, rust-unic and zip
findings (`target/voice-hello-native-deny-final-2.log`). The earlier native audit also reported
the DER bundle corrected above; the final native run has no remaining TLS-root/verifier finding.
Those findings have not been suppressed or resolved by the TLS correction. Native and root
full-suite validation is pending against the final locks. The first obsolete-lock root run
was deliberately stopped before tests and is not accepted validation.
