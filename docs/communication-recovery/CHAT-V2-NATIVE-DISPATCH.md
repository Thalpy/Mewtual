save/read operations. This continuation now connects real native founder rows
and plain local message saving. Frontend integration, own-history dispatch,

off; the real Tauri fixture selects the same native implementation for tests.

## Native rows and local writes

The one actual server table is a closed Legacy/TextV2 sum. Actor, file, voice
and Studio selectors explicitly choose Legacy; a native row has no dummy actor.
Legacy reload reserves its exact table slot before voice registration, rejects
cross-backend collisions and moves the replaced whole owner outside both guards
before disposal. Legacy removal still requires the actual actor stop proof.

Native founding captures actual ACL/window, generation and original authenticated
mount before bounded parsing/scheduling. Its nonzero 32-byte request ID and frozen
settings drive the six consuming Root stages and exact stored-runtime selection.
Final publication repeats original mount/generation/closing checks under the real
table guard. An identical retry's passive candidate cannot close the installed
Source. The result identifies `backend: text-v2` and a request-context correlation;
it does not establish transport, invitation support or a complete usable group.

Plain sending captures the actual row/selection/incarnation/full account scope
before scheduling. A nonzero 32-byte retry token and exact context/channel/body
are preserved. Phase one restores runtime/key custody before another native
commit acquisition. Final preparation owns counted Source work: persist, UI,
Store and table acquisition are TRY-only. A preallocated, genuinely checked box
holds actual native guards through the admitted file job, independent of the IPC
observer. SavedLocal is reconciled using the same request to obtain its original
action/ordinal. No receipt or network publication follows from that local result.

## Whole-close ordering

Native whole-close bypasses the Legacy freeze barrier. After continuity permits
irreversible close, it validates a pure-native table, publishes global bootstrap
closure before any fallible controller probe, and SC-fences original rows. Their
owners stay installed while Root Source/SDK/work/facade drainage runs without UI
or table guards. Refusal retains the same fenced rows. Only successful actual
drainage permits extraction and outside-guard disposal. Mixed Legacy rows refuse
before effects; their separate save/freeze/stop barrier cannot be bypassed.

## Original per-row fence

`NativeChatSourceOwner::close_handle` issues an opaque handle to its original
counter. It has no Source/Host/issuer backlink or positive key permission.
Calling close is the existing SC atomic fence; it performs no notification,
allocation, wait or payer release. Dropping a handle closes nothing. Retained
handles preserve the original counter's trusted custody; the actual Root
producer supplies fee-only RuntimeMetadata, without an SDK/physical reference.
Handle disposal still belongs outside native guards.

Root captures that handle before moving its real SourceOwner into the canonical
Entry. Its one paid runtime selection caches a clone and exposes only
`close_original_cached`. Native row retirement can therefore stop new primitives
without borrowing the runtime, Source book or issuer. Existing whole-owner
retirement and actual key/loan/SDK/TCP drainage remain separate requirements.
No usable Leave or durable Retired transition is implemented by this fence.

Five new RT regressions cover original prepared purposes, lock/unlock, admitted
Ends, another source, passive payer lifetime and the exact Source-counter CAS
with no notification under a guard. A real two-row NativeRequired Root test
preborrows the first runtime and holds its actual book while closing its cached
counter, then requires a real signature from the other row. UI credentials in
these Root fixtures remain synthetic. All 32 RT lifecycle cases passed, as did
all five selector cases (27.99 seconds) and the genuine runtime-loan case
(5.79 seconds). The initial reused 27-case RT binary was rejected as stale;
only the current 32-case execution after package-specific cleanup is evidence.
The full RT package also passed all 74 cases, and the complete affected Source
cohort passed all 79 cases (303.28 seconds), zero failures/ignored. Strict RT
Clippy passed (2.51 seconds). Full Root/native/frontend validation of this
continuation and actual native integration remain pending.

## Remaining warm vertical

The Legacy shutdown barrier owns both UI commit and the entire server table,
so it cannot enclose native Source drainage. The new native-only close path
bypasses it. Native final preparation is counted work:
never await that UI guard with such a preparation alive. Final admission must
try the actual owned guard, returning/dropping whole preparation outside guards
on contention before any wait/retry. The implemented native path releases its
short table borrow before drainage; its new final-preparation race coverage is
under validation. Full native acceptance remains pending.

Own-history dispatch must still fund serialization separately from its paid Root
page and retain exact row/mount/generation checks through response publication.
Its result must identify this member's saved originals rather than pretend to
be a complete group projection. Native replies/edit/delete and usable per-row
Leave/Retired also remain unfinished.

The frontend needs its real backend DTO branch: native founder intent has a
stable 32-byte ID, member intent has a 32-byte token, and stored own-original
pages cannot masquerade as complete group history. Successful native founding
must not call the current unsupported shared-name/livery writer afterward.

Two-row local saving now has focused native evidence above; the final warm
vertical still requires broader races, complete native gates and frontend use.

Joined/Add production sources, multi-member archive, transport, full projection
and admin ledger, operational cold restore and combined 20–50-member acceptance
remain open after this warm local vertical. Physical two-device acceptance is
