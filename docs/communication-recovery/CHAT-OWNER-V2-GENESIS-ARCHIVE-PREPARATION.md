## Owned source and API

A checked consuming constructor takes the actual opaque `FrozenFounder`. On a pre-candidate
refusal it returns that SAME original owner in a sanitized refusal wrapper, allowing the caller
to finish an uncached source without losing it. The small boxed owner/error storage must enter
the host invoice. The preparation exposes no source setter,
`&mut FrozenFounder`, raw snapshot constructor, Server/device escape or consuming-error API that
drops a possible candidate. Its fallible preparation method borrows that retained owner and the
SAME actual ChannelSync. Before any record, key or random work, require the immutable checked
private-S0 view: uncached, retired, replaced, restored/equal-labelled or changed sources refuse.
Original Fresh/scope/public-frame and complete provider/allowed-metadata equality remain mandatory
at this boundary. Epoch/authenticator checks alone cannot bind the private snapshot.

The actual private S0 is frozen BEFORE successful construction of this wrapper. The wrapper never
resamples S0 or allows its source to be swapped after encrypted archive pages exist. Final checked
borrow repeats the complete original-source/private-S0 validation, not a cached boolean/digest.
These checks establish CURRENT equality of the complete source, not a global mutation-history
counter. Changed-then-byte-exact-restored metadata may pass with the SAME still-live original
source/reservation; taking/dropping/replacing an original negative lifetime cannot be repaired by
restoring labels/bytes. Observed checks are not an atomic storage admission; the actual App saver still holds original
scope/head/native guards through final covering save and Current install.

Construction takes the expected vault domain; later preparation takes the original db-key bytes
and injected crypto RNG from the trusted host. A narrow internal original-scope getter requires
the original scope still matches, management was required, and its captured label AND live
original reservation exist. A bare staged label is insufficient. The fixed domain cannot later
be retargeted. Preparation requires that SAME original managed initialization scope and derives
context from the source's actual Profile/Admission/header/image. A scalar vault/key argument is
not a mounted-key capability: the future actual Store must provide its own original key/domain
under the real mount, never accept those values from native IPC or remote data.

On first successful preparation, cache one immutable package bound to that exact vault and key.
Keep a zeroizing domain-separated key binding rather than the original secret key. Later retries
must use the same domain/key and return the SAME sealed bytes/IDs without RNG/re-encoding. A
different domain/key/source refuses without altering the original package. Checks repeat after
first bounded construction before returning any view. A proven local failure before a complete
package is returned has released no archive/canonical effect; it cannot refund an actual original
work grant or authorize a later reparenting.

## Exact package

Decode/verify the source's actual public Profile, Founder Admission, header1 and full state image.
Build the exact Genesis3 batch in canonical typed order Profile/Header/Admission; Header retains
the original signed envelope plus complete canonical public image. Bind vault/Profile/actual
Genesis operation body and real genesis consistency through `cold_records`, not descriptor labels.

Seal that one bounded private record page with the dedicated private-page key. Construct manifest
sequence1 with the same actual group/Profile, no previous manifest/source head/preceding header,
the real resulting header1, Genesis body and one GenesisRecords descriptor of3 logical rows.
Its descriptor uses the actual sealed page ID and exact plaintext byte length. Seal the manifest
once using the same dedicated page format. Self/new-head private IDs never enter public state.

The package owns only these immutable sealed record/manifest frames and exact context/source-S0
metadata. Checked views borrow the frames/IDs and source's original private snapshot bytes; they
cannot construct a new source, retarget content, reveal raw private provider through a native
command or claim durable children. Once actual I/O is possible, the App owner/journal must retain
the whole package across caller cancellation and uncertain writes; it may not reconstruct pages
by re-signing/resealing a matching public Profile.
