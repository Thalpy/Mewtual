## Selection before any large read

The trusted private physical-opener policy must explicitly configure source-read caps and an
actual shared account. Default/unsupported readers remain closed. Requested group1..256/full
signer plus the actual mounted AR2 vault/root select the existing fixed target hash. No caller
path, recursive listing, lifetime scan or missing-file-to-new-founding fallback is accepted.

Before reading ANY small or large buffer, acquire ONE complete prepaid read reservation
`READ_FEE = 3 * MAX_BOOTSTRAP_SOURCE_FRAME_BYTES + 1MiB`. Capture the actual
root/marker/target/origin objects and their session identities. An authenticated bounded marker
locator supplies only invocation/debit labels, needed to derive the fixed flat control names.
The locator must parse COMPLETE marker tag/version/framing/EOF and check requested group/full
signer and actual vault/root before returning labels. The existing full marker decoder then
checks it AGAIN against the independently opened actual immutable debit, never merely its own
labels. This avoids both a circular lookup and inventing an origin-to-authority shortcut.

All four fixed controls are classified: actual debit, current intent, stage and repair seed.
The initial reader supports only a complete exact SourceSaved current with no stage/seed or
other ambiguity. Every unknown/partial/disagreement preserves/refuses; automatic exact small
DATA repair is a separate required consumer, not an unsupported-record cleaner. Terminal
context/SourceId/marker/counters must match the actual debit/origin. Parent digest alone is
not an actual prior-SP witness; the terminal's independently authenticated historical record
is DATA from the original producer, not a reminted warm SavedTerminal receipt.

The new capture owns exact selected-small-frame hashes/held objects, mount/root negatives and
actual resource metadata. It contains no Store, key, creator sender, session loan or runnable
task. It cannot be adopted across a new mount by matching files/path/serialized labels. An
actual Current consumer additionally requires the new mandatory namespace3 and its own group
pin/head/scope authority. AR2-only source DATA cannot silently become a Current host.

## One actual read pass and resource lifetime

The NEW actual reservation above covers the real raw/cipher/plaintext overlap,
retained verified-public-genesis additions and all fixed control/path/return scratch through
one original strong fee. It is independent of the spent original source-write allowance. No parsed count,
timeout, restart or configuration relabels an old write unit as unused.

The one non-Clone read Work retains the fixed source.bin/records.bin/manifest.bin held Files,
actual expected terminal
context/whole SourceId, original negative capture, resource owners and an ephemeral zeroizing
dbkey copy. It performs at most the fixed bounded raw read plus the existing offline source
opener, outside all admission/pin/canonical/Root/registry writers. After the copied opener
ciphertext drains, read each separate genesis page with capacity exactly its authenticated
embedded-frame length plus one EOF probe; compare complete bytes to that already verified
embedded frame. Record frames are bounded by MAX_PRIVATE_CHAT_PAGE_FRAME_BYTES (64KiB plaintext
plus fixed crypto framing); the actual closed genesis manifest cap is1110B. Page buffers drain
serially. Include these buffers and fixed path/control/capture overlap explicitly with the
256KiB nested DATA inventory in the extra1MiB; do not count them as free merely because the
three large buffers have a conservative maximum. Capture metadata has bounded root/target
paths and derives each closed control/page name temporarily, rather than retaining9 full paths.
The named invoice pays four simultaneous complete paths at TWICE their bounded length because
PathBuf clone/join/push may grow capacity. The warm write worker's separate metadata assertion
was also corrected for that growth, still within its existing512KiB fee. The read fee is larger.
The result covers all three artifacts, not only the source's embedded genesis. The opener needs dbkey for
nested private-page verification too; this is not a source-key-only capability. No decoded
SDK load, source rewrite, large-file repair, scope write, network submission or native DTO is
part of this pass. Duplicate/lost handles cannot run the same read twice. A failed/abandoned
Work does not reconstruct itself; a later trusted local attempt acquires a distinct new fee.

No physical-session loan is needed for this strictly read-only Work. It cannot create, write,
sync, remove or repair any file. Store Drop may allow a new mount while an old read drains;
the old result must refuse through its original negative/mount identities even if every file
and label stayed identical. Idle captures and returned DATA retain no session/key/Store. There
must be no queued mutating effect after read cleanup.

The completed output is opaque OpenedBootstrapSourceData plus its SAME actual retained fee.
Final original mount/root/target, small-control and named source-object proofs follow every
large read/hash/AEAD/signature operation. Short writers never await a long read/result mutex;
use immutable completion or try_lock. No full source read/hash is repeated under Root for a
lost return. All large plaintext/cipher buffers and completed metadata precede their last fee.
The public genesis DATA seed builder may borrow this output outside writers under a SEPARATE

## Required regressions and remaining boundaries

- Actual warm exhausted SourceSaved, owner/Store Drop, new physical open, new paid source
  capture/read and exact original source/genesis/S0 DATA equality; no old warm registry token.
- Refusal without actual policy/fee, one-byte-short pressure before read, exact invoice lifetime
  after Store/caller Drop, and release only after read/result cleanup.
- Wrong group/full signer/vault/root/invocation/debit/context/SourceId; complete foreign marker,
  unknown/partial/conflicting stage/seed, missing/corrupt/oversized source preserved as incomplete.
- Original cancellation, root/target/current/source replacement while the large read/opener
  waits, no stale positive result on remount, and duplicate/lost read return exactly once.
- Another group's actual source writer progresses while the read has completed its large
  opener and waits at a barrier. The reader holds no global writer or long shared mutex.
- Cold terminal DATA cannot issue Fresh, repeat Server::found, refund old write budget, create
  Current or bypass the mandatory namespace3/group-pin/initialization transaction.

The actual APIs are `ArchiveBootstrapCatalogPolicy::with_bootstrap_source_data_read`, configured
before the private physical open, and `ServerStore::read_saved_bootstrap_source_data`. The
returned `RetainedBootstrapSourceData` owns the original fee and borrows opaque opened DATA;
`validate_original` rechecks the original mount/controls/objects before a later consumer. It
is not a native disclosure lease. Any downstream seed/node must retain SEPARATE actual SDK and
non-SDK dependent-copy/provider/metadata fees; negative scalar limits alone pay for nothing.
Ten regressions are authored UNRUN and actual static review is clear. Only direct formatting,
