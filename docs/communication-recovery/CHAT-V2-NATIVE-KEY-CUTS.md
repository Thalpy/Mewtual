# Native key cuts (13 November; production factory incomplete)

The isolated founder integration branch connects concrete native lifecycle checks
to the actual SDK, bootstrap Profile/Header and ordinary-member primitives. It
does not yet capture a native command or authorize production Chat V2. Chat V2
remains disabled.

`catcoms-rt::native_chat_key` separates affine UI/source close owners from weak
command observations. Preparing one of five closed-purpose cuts pins only the
original negative metadata. Entering a primitive requires that same source and
purpose, the captured UI generation, current authorization and both open owners.
Admission uses at most one CAS per counter, with a final negative check after
both increments. Contention refuses without a retry loop. Retiring an owner
prevents new admission and waits for admitted Ends; it never reports a timeout
as successful drainage. A fresh authenticated UI may access the same still-live
source, while an old command cannot adopt the replacement session.

Host and generation constructors now require independent fee-only custody. Host
payment follows Host pins; generation payment follows its actual Counter through
prepared cuts, Ends and drains. CLOSED+zero proves work ended, while an unentered
cut can still retain metadata and its payment. The preissued retirement observer
waits for CLOSED+zero; first idle retirement wakes it exactly once. Retire/owner
Drop and notifications run outside native/registry/Store/Root guards. Whole Host
close is SC-only and runs before locks. Records must not be stored in Counter
custody, which would create a cycle through their drain. The actual native
registry must still prepay retirement slots and bound/coalesce waiting tasks.

The caller keeps the prepared cuts and fixed End batch outside all Root, Core,
Store and native guards, on both success and unwind. Partial admission retains
its End there too. No last metadata or custody destructor runs in the primitive
tail. These application counters are not SDK allocation or process RSS bounds.
The public trusted-host constructors authenticate neither arbitrary atomics nor
an arbitrary custody box. Only the missing checked native factory can supply
that binding. Participating generation/authorization/close publications must use
sequential consistency; existing native publication sites are not yet wired.

Root retains an immutable private `Library` or `NativeRequired` origin through
creation, planning, source save, Current, empty promotion and the whole member
Host. Public library wrappers refuse the native origin, including cached hits.
Private native routes preflight before bookkeeping and repeat the final check
after source/cell observations immediately before member-save custody moves.
The SDK cut runs after actual file/debit proofs and before consuming the SDK
unit. A proven local refusal preserves that same unit; primitive entry still
spends it irrevocably. Returned SDK/raw signature results are cached before late
checks. Unknown entered results never authorize a second primitive call.

Sync checks the concrete bootstrap cuts immediately before Profile/Header key
entry and the member cut before Core's `begin_key`. Existing node, scope, full
signer and plan checks remain. Cached raw is DATA and deliberately invokes no
new primitive or native cut; callers must still enforce Root/native current
authority. A successful cached Sync return alone supplies no current permission.

## Executed focused evidence

Windows local execution passes 17 runtime lifecycle cases, 10 retained bootstrap
cases, nine member cases, five actual Root SDK/source cases and two new whole
warm Host/member-save cases. The whole warm cases use real encrypted source and
outbox storage, but synthetic host atomics and test native custody. They prove
original-owner ordering and retry behavior, not a real AppState command. Both
source closure and generation publication at the final save edge preserve the
same prepared original; reauthorization saves it without another RNG draw.

Read-only adversarial reviews corrected last-Arc destructor placement, cached
SDK preflight and the final save-admission race. No blocker/high/medium remains
in those reviewed slices. Strict Clippy passes for rt/sync/net; ambient and Store
filesystem gates pass. Exact-source complete suites remain required. Hosted
cohorts reject zero, wrong counts and selector drift. Linux still lacks the
bounded settlement/promotion directory inventory needed for the whole warm path.

## Remaining production work

The owning native index transaction cell, durable Pending/network reservation,
checked command capture, actual source/row/mount/key binding and device factory
are unfinished. No runtime row or native issuer can be constructed from these
private library routes alone. The backend/mounted-vault sum, cold operational
owner and Leave, joined pins/Add/archive/transport, later-prefix/multi-member
authoring, UI/admin exposure and combined acceptance are also open. The weak
Root origin identifies one live lifecycle; it is not a persisted birth receipt.
An actual producer must bind both before enabling any SDK or key path.
