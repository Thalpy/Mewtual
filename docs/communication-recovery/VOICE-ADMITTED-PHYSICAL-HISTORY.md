## Original native history

`NoIntentYet`, `KeyOnly`, or a separately paid physical history. There is no
second winner registry. A new fixed main-only physical key-admission command
binds that history to the actual original activation, UI generation, executor,
join and generation permit **before** granting its sole SDK computation.
Key-only and physical purposes cannot adopt each other. A mismatch after the
exact current native owner check returns the existing typed no-admission
`refused` shape, with no permit/join. Unknown owners, UI loss and transport
errors remain unknown.

Native receipt serialization keeps the original history/Handle owner through
the capped output construction and `IpcResponse` handoff. Tauri's subsequent
queued/retained String is a stock framework copy outside this payment; the leaf
does not claim an application payer follows that body after handoff.

The history transitions only from Unstarted to Admitted with the exact physical
Row serial, then ActuallyCollected. The first transition occurs in the original
UI commit -> Coordinator -> Index turn, before any native RNG/curve work. A closed
Unstarted original can produce an exact not-started receipt. A retained closed
parent still in the initial NoIntentYet state can instead report
`no-physical-intent`, containing only its owner: **no executor, join, SDK or Root
history proof**. A missing/forgotten parent is NoProof. Neither missing Rows nor
collected Rows can be reclassified as never started.

Native collection retains every existing actual-return gate, including
`State::admitted_returned()`. After removing the actual last Row from the shared
64-slot index, an outside-guard owner keeps the SAME Row payment while its actual
allocation deallocates. Independently custodied Session and public output must
already have completed their actual body/header destruction, including every
private weak tail. A paused destructor or in-flight reaper is not returned.
Only then does it record
ActuallyCollected. Independent key/Root/task/SDK owners have separate payments
and are not certified by this receipt. The history has no Handle, Row, Actor or
positive-grant backedge; its original observer and body share a plain outside
payment through actual deallocation.

Parent activation ACK may occur after known setup. Parent Forget still refuses
until the physical terminal receipt is explicitly acknowledged, alongside all
its independent original key/Root/task gates. Lost close/collection replies
recover the SAME paid history without fresh ordinary capacity. Receipt identity
is a domain-separated hash of the original owner, UI generation, executor, join,
terminal kind and exact Row serial where applicable.

## Browser composition

Broker ABI53 uses the SAME window symbol, byte ledger, caps and provider queue.
An older retained broker requires reload; it is not replaced beside outstanding
cleanup. A distinct retained native-adapter brand chooses physical purpose
before selected-key admission. The public physical handle has only `attempt`
and `close`; neither an Existing key nor a caller point/private key/seed can be
adopted. Same-window adapter module reloads reuse their weak brand registry.
The concrete production adapter must wrap the stateless trusted native invoke
bridge. Its brand prevents accidental profile mixing, not arbitrary same-realm
JS closures from capturing other objects; no capture-free claim is made for an
arbitrary caller-supplied invoke or Clock implementation.

Initial native setup and real browser ECDH/HKDF run inside the SAME original
selected-key SDK job. Waiting for another provider position behind that job
would deadlock. The constructor uses the retained nonextractable private key,
the admitted version2/profile1 transcript and its separate bootstrap seed
label. It never calls the Existing channel factory, old Status, old setup ACK or
old KDF. After actual construction SDK return, known native setup precedes
parent ACK and key publication ACK/SDK settlement. At actual job return, a live
bootstrap transfers its original execution contribution to one retained
physical position before another job is admitted; there is no second pool.

`bootstrap-only` does not mean ready, setup-ACKed, admitted or RTC-capable.
Native browser-setup custody remains held. A future authenticated operation31
SetupAck must release only that original custody **after** the actual SDK
construction returns. Negative settle/collect closes first and is never used as
a positive ACK. The separately composed operation31 consumer has its own
exhaustive stage/Slot/Root/Work/parent return gates; this driver does not bypass
them or send SetupAck, Register, Observe or Cancel. A future sender remains open.

Close joins the actual original SDK job and entered public-handle callbacks
before discarding keys/buffers or returning heavy metadata. A genuine physical
terminal permits a final negative ACK/waiver request. A tiny descriptor retains
the SAME prepaid receipt/native-adapter identity and retries parent ACK then
the exact receipt ACK. Lost/error/NoProof replies do not reconstruct a driver,
regenerate a key, declare ACK delivered or infer collected history from absence.
The shared broker bounds these descriptors together with live channels.

Explicit window last release may cede only those final negative retries after
actual pending invoke/timer owners return. It does not claim native received
the final ACK; unreceived requests may retain bounded native history until real
process cleanup. This last-release entry is available but no production App
activation/shutdown consumer is connected by this inactive leaf.
That eventual consumer must quiesce new creation and join/close all live
physical channels **before** abandoning the current descriptor snapshot. The
method is not a permanent broker-shutdown latch; later allowed channel returns
can register new descriptors. Their retry ownership must not be silently lost.
