## Initial durable intent profile

After a covered Add, the warm founder can issue the next invitation through
the same native job. The journal binds that intent, attempt and signature to
the exact encrypted selected Head. It preserves the first invitation files
and gives an exact retry at the same parent the same signed packet. The next
JoinRequest must match the new journal and pass the SDK package preflight.
The Add writer repeats the journal check before covering the later reservation.

The real `NativeTextMemberJob::prepare_invite_intent` now looks up its exact
token/settings/public plan before asking the retained node for a new unsigned
original. The new closed `text.pages/invite.intent.v1` family stores that
original preimage and plan under a separate AEAD key domain. Its context is
derived from the actual original source encoding, genesis frame, scope nonce
and held pin. Current4, the selected G1/member parent and native command are
checked around IO; no caller path, context digest or signing callback enters.

This initial profile reserves **one object and 8 KiB per context**, separately
from Head1 counters. Its authenticated format fixes both limits. It never
replaces, evicts or deletes the object, and refuses another token/settings.
The original native-only warm Host owns the affine initialization opportunity;
there is no cold/library adopting constructor. Missing after creation,
malformed/unknown/torn quota or format and replacement directories/files are
errors. A cold recovery consumer must require the existing journal and cannot
interpret absence as an empty quota or recreate that initialization opportunity.
Wider history/retention needs a separately versioned producer.

The Host pays a named independent memory invoice before allocating the journal.
Its actual pages/file handles drain before the retained vault physical-work
lease. All reads/writes stay inside the same synchronous RuntimeLoan, so no
detached writer or global text-lane registration is introduced. AEAD candidate
preparation and its RNG run outside Current/Root writers. The candidate is
cached before create/write; the same warm owner can complete only its own
exact partial prefix. Unknown create entry is held. File and directory barriers
and exact identity/byte checks precede covered unsigned success.

Unsigned preparation returns only its preimage hash and expiry. It runs through
the same exact lookup that precedes signing.

## Signing records and local receipt

`invite.attempt.v1` and `invite.raw.v1` are separate immutable files under the
held `text.pages` directory. They share a versioned AEAD domain and encode a
closed quota of two objects and 1 KiB total, capped at 512 bytes each. Each
authenticates the original context and intent ciphertext commitment, and Raw
also authenticates the attempt ciphertext commitment and the original 64-byte
signature. The same runtime caches each sealed frame before create, and can
finish only that frame's exact prefix using its held file identity. It refuses
preexisting attempts, orphan Raw, and missing, replaced or altered covered
files. Ordinary Head/O/H/WAL/I/S accounting remains separate.

After Raw file and directory barriers, the job checks actual Current4, the
selected founder parent, the original command and cancellation. The resulting
opaque `NativeTextSavedInvite` carries the signed binding ID and original expiry.
The receipt owns a separately paid packet. The original remains inside the
Host, which can return an identical packet after a lost reply. A process
restart leaves an unresolved attempt on disk for future recovery.

## Invitation packet

The outer binary frame is a length-prefixed
`mewtual/chat/native-invite-packet/v2\0` tag, a big-endian u16 version 2, and three
length-prefixed fields in order: the signed invitation binding, the original
encoded group policy and the original routing reservation. The decoder caps
each field at 1 KiB and requires exact end of input. It verifies every
representation's signature and both signed body commitments before using the
policy or reservation.

This profile requires a founder signature and the same founder's epoch-zero
peer-to-peer policy for the same group. The reservation decoder reconstructs
the canonical full libp2p PeerId and transport commitment from the Ed25519
public key. It checks group equality, TCP reservation kind, a nonzero port and
zero certified contacts. The reservation encoder emits the same bytes as the
original unsigned producer. Packet validation establishes neither a trusted
group pin nor current membership, expiry, reachability or permission to dial.

The Host assembles the separately paid packet outside writers from the retained
policy, original plan and verified signed binding. Raw coverage still runs if
packet assembly refuses. The receipt is created after the Raw barriers and
current checks, and the original native job checks cancellation and authority
again before returning it. The connected join path uses the authenticated
transport identity. The gated desktop preview verifies the signed packet and
expiry under the original authenticated UI session, and reports zero certified
routes for this packet profile. Its scope is authenticated metadata.

## Read-only journal recovery

`NativeTextMemberJob::inspect_invite` opens the three fixed journal names
through the original governed Current and selected genesis parent. It takes a
separate memory reservation and vault lease. The reader derives its context
from the original source, genesis frame, scope nonce and held pin. It compares
the exact request and retained route and checks the full genesis anchor.
Neither the warm signing slot nor a newly initialized member lane participates.

- A valid intent with both signing records absent yields `IntentOnly`.
- A valid linked KeyAttempt with Raw absent yields `KeyAttemptHeld`.
- Three valid records and a verified signature yield `SignatureRecovered`
  with the original signed binding ID and expiry.

Missing intent, orphan Raw, torn or swapped records and stale Current refuse
without mutating the journal. The first guard captures bounded bytes from
read-only handles. Authentication and signature verification run outside the
writers. A fresh guard rechecks the actual group and the same directory,
file identities, bytes and observed absences. Native command and cancellation
are checked again before return.

These statuses describe observed bytes. They grant no new key attempt,
publication capability or covering save receipt. The warm native job is the
first caller. Reopening a promoted operational owner after process restart and
publishing a recovered invitation remain separate work.
