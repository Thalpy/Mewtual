# Native text warm vault factory

Status: implementation under focused validation. Production selection remains
off. This connects real native authentication to the opaque selected3 storage
owner; it does not implement a working Chat V2 server or message send.

## Native entry and authentication

The outer synchronous Tauri router intercepts `unlock` only under trusted Rust
configuration. The production constant is false. The renderer cannot select a
protocol or supply a mounted owner, permission flag, directory or session atomics.
Normal command inventory and the existing backend fallback remain unchanged.

The router requires Tauri's resolved command ACL and the actual main window and
webview. It captures the original UI generation before bounded argument parsing
or scheduling. One native permit bounds outstanding unlock work. It retains only
the bounded zeroizing secret and drops the parsed invoke body before dispatch.
A completely unpolled invocation cannot adopt a later lock/unlock generation.

Native-mode startup constructs a fresh AppState at generation1, authorized0 and
lock requested, before managing it or creating tasks. Legacy startup keeps its
existing defaults. Zero remains an unauthenticated Root marker; neither router
nor worker normalizes an already captured generation. The real frontend also
obtains its authentication generation through the existing native lock barrier.

Blocking authentication captures one finite physical metadata capsule under the
store guard, then verifies outside that guard and the UI commit mutex. The same
capsule retains the original Host and physical negatives through native unlock
finalization. Whole-vault closure is distinct from an ordinary UI lock; a correct
secret cannot authorize a permanently closed owner.

Selected3 verification authenticates one actual critical wrapper transaction and
compares its derived key commitment with the mounted hierarchy. A valid wrapper
copied from another vault does not authenticate access to retained keys. A valid
same-DEK passphrase rewrap remains acceptable. No keys are returned to native and
the existing Legacy verification API is unchanged.

## One original fresh owner

This milestone accepts only a fresh installation. Native requires successful
creation of its new directory, rather than interpreting an existing directory
as an absent or different vault format. Root independently acquires the real
lifetime vault session before its bounded fresh-directory check. Only the exact
held session-lock file may be present; a missing wrapper beside retained data is
not permission to create new keys.

`NativeRegistryInstallation::prepare_fresh` pays its native physical/preparation
invoices before Current preparation, KDF or file effects. The initial Store opens
its mandatory lower inventories once. That same Store consumes critical
activation, authenticates its Empty G1 catalog and privately attaches only the
previously absent pending catalog. It neither clears existing lineage nor
replays constructor-only lower gates. The existing archive2, Current3, member5
and native1 preparations then retain the same keys, mount and session.

The original installation moves into the existing index2 upgrade and the new
owning `NativeTextVaultUpgrade` continuation. All successor errors retain the
same original transaction before returning. The final transfer moves its whole
UI owner and selected3 physical allocation into `MountedVault::TextV2`; no raw
Current, Store, index snapshot, Source, SDK or backend extractor is added.

Initial preparation errors that occur before an owning plan exists are terminal
for this warm process. Its files are preserved and no alternate opener is tried.
Cold classification and operational restore remain required before activation.
Errors after an owning plan exists retry that same plan without replacement.
Losing a renderer response does not cancel the owned native storage task.

A lock may win while metadata work is already finishing. The completed vault
can remain mounted and locked, but the old invocation cannot authorize the UI.
The next caller must authenticate its own secret against that same mounted
owner. A retained plan created with a correct secret is never evidence that a
different retry secret is valid.

## Scope and remaining work

This is a mount/authentication checkpoint. It returns an empty list only for the
fresh empty vault; historical index DATA does not create Legacy actors. Root's
new founder-only Birth/Activate storage operations still have no operational
native founder producer. Native key admission, original transport reservation,
whole retained creator/Host and member command dispatch remain unfinished.

The Svelte continuity commands and lock snapshots still use the Legacy store.
This checkpoint therefore does not establish usable Svelte unlock or close,
cold restart, joined-member authoring, governance Add/Remove, owner-offline
delivery, projection/admin history or multi-peer recovery acceptance. Chat V2
must stay off until those paths are implemented and verified.

Logical Root invoices and the native single-flight/input bounds name specific
owned buffers and work. They do not establish a process-wide RSS bound, account
for all KDF/Tauri/browser allocations or prove physical-network behavior.
