# Concrete scope integration and cold genesis roles

The warm scope, physical group task, artifact worker, canonical writer and unexposed owning
caller are declared together in the local integration draft. Six pre-seed scope tests and ten
genuine owning-caller tests have passed, including both scope-write failure orderings, retained
head/owner identity, cancellation and unrelated dirty-table preservation. The admission-owner
payment correction also passed six focused lifecycle tests and three revocation tests.
Root owns the serial build/test pipeline; complete-suite evidence remains outstanding.

This does not enable Chat V2. The caller retains the same graph in an unbound node and exposes
no authoring, projection, runnable server or native result. Cold read and Current ownership are
separate integration packets with the exact gates below. Partial genesis repair, seed settlement,
later-head recovery and operational chat remain required.

## First connected packet: actual warm scope tests

Keep `chat_admission/v2_current.rs` separate from the generic legacy issuer. Its existing
`reserve_v2_genesis_initializing` caches `V2CurrentPreparation` before row insertion, fixes the
original source nonce/Fresh provenance at revision1, and owns the genuine Some(1) reservation.
`finish_v2_genesis_current` saves the head under clean Init1, latches the actual head before
advancing BOTH the row and the SAME `AdmissionOwner` to revision2, then flushes the latest
table and repeats complete physical/source/writer checks. `resync_v2_genesis_current` has no
head callback and accepts only its already retained CurrentSaved phase. Do not merge these
three roles into the generic `finish_chat_admission` or `reservation_locked` paths.

The next actual call chain is:

1. Produce genuine SourceSaved using the existing original-founder factory. Drop its old
   creator/Store; finish a NEW `PreparedV2CurrentLayoutStore` physical declaration. Read that
   exact source with the actual new paid reader, then `ServerStore::prepare_genesis_seed`.
2. Through the completed layout wrapper, call the private
   `prepare_genesis_group_namespace(&GenesisSourceDataRef)`. Factory implements its actual
   vacant admission/pins/canonical/Root checks and registers the original negative task. Its
   first role never adopts an already present directory. Retry directory creation on that
   same task and obtain its actual `SavedV2GroupDirectory` after file/parent barriers.
3. Root's `PreparedV2GenesisActivation::prepare` caches all exact metadata candidates outside
   writers. Under `with_vacant_v2_genesis_admission`, obtain `task.lock_vacant` and call the
   actual `save_seed`. Retain its actual Arc before any scope mutation.
4. Acquire `reserve_v2_genesis_scope_buffers` outside writers; call
   `reserve_v2_genesis_initializing` with an owning `Option<V2CurrentPreparation>` slot. A
   failed first flush leaves the SAME cached slot/row1/life and dirty latest table.
5. Prepare Root's actual paid `PreparedV2WriterRegistration` outside writers. In the private
   scope finisher callback, take `task.lock_initializing_owner_namespace`, install that SAME
   registration before Root, then take `lock_archive_root_for_writer` and call Root's `save_head`.
   Root compares the actual activation Arc, not merely its ID.
6. Let the scope finisher complete Current2. Root retains the complete source/SDK capsule,
   scope preparation, task, paid writer and head. Its later node-pairing callback is followed
   by `resync_v2_genesis_current` through the SAME node-derived source view. Do not expose an
   runnable/native Current until the separate exact seed-settlement/source/head closure also succeeds.

`canonical/v2_registration.rs` implements the private
`current_vacancy::InitializingV2OwnerNamespace` consumer. Factory owns that real inner guard
and its `registration_parts` borrow of the actual initializing admission/V2 runtime. Its outer
`InitializingV2GenesisOwnerGuard` delegates `install_writer`; the proof-only Root guard has no
writer method. Neither role uses a v1 canonical permit.

The owned task retains no Store/key/session. Factory has frozen directory retry as private
`task.retry_directory(&mut self, &ServerStore, &GenesisSourceDataRef)`, with explicit actual
Store validation on every call, and `saved_directory()->Result<&Arc<SavedV2GroupDirectory>>`.
The three borrowed role guards remain tied to their original Runtime writer, with lock order
admission -> pins -> canonical -> Root. Scope flush runs with Runtime only, after all other
guards have dropped. Its synchronous 32MiB I/O can delay another group's scope operation;
that fairness limitation remains required later work, not permission to invent a persistent
scope execution grant or skip the actual writer.

Focused tests belong in a new `chat_admission/v2_current/tests.rs` child and must use that
real chain rather than a fabricated task, receipt, admission owner or watch:

- initial scope1 -> exact saved head -> scope2; identical nonce, historical provenance,
  planned revision1 and owner identity through the transition, plus actual persisted row2;
- pre-rename and parent-sync failures during the first scope1 flush: dirty1 resync releases
  Root before flush, retains the original slot, and later obtains a real clean Init1 permit;
- scope2 flush failure after the head callback: retain HeadSavedPendingCurrent2; callback
  runs once, owner identity stays the same, and retry never issues an Init1 permit at row2;
- original source/mount/task/writer cancellation or fixed control replacement during final
  reads/scope flush refuses success; equal source bytes from another paid capture cannot adopt;
- another group inserted between failed attempts survives the later whole-table resync;
  any same-group foreign-signer Current/Retired/Initializing row or owner rejects first genesis;
- one byte short of the same-pool scope buffer fee refuses before row mutation; independently
  funded metadata/source/SDK/writer payments stay retained until their actual owners drain;
- after the node move, CurrentSaved-only resync cannot call the head callback or create a new
  owner; a bounded thread/channel harness pins the no-recursive-Root-lock path.

## Separate cold Initializing1 issuer

An existing persisted row1 must not enter the vacant constructor. Introduce a private
`resume_v2_genesis_initializing` entry with these concrete inputs:

```text
actual ServerStore + GenesisSourceDataRef
actual Root ColdV2GenesisActivationSeed
actual Factory cold-own group task
owning Option<ColdV2InitializingPreparation> + same-pool scope buffers
```

Root's receipt is a NEW actual cold capture/barrier owner of the complete seed and its
original candidates, independent current-layout/source identities and held group directory.
It is not a parsed seed, an old warm SavedSeed or a caller's status. Factory's separate
`from_cold_activation` consumes/borrows that actual receipt and the new source/SDK observation;
it never routes through mkdir/vacancy, accepts an unknown partial directory, or adopts an old
task by equal IDs. Root must freeze the exact receipt/role method signatures before source.

Under Runtime, the scope issuer requires the exact source domain/group/full signer/nonce/
historical Fresh attempt/revision1/Initializing row, no companion signer and NO runtime owner
or competing predecessor. It verifies the real cold artifacts under the proper subordinate
guards, then caches the entire new preparation before inserting its NEW mounted
`AdmissionOwner`. It neither rewrites the row nor calls `reservation_locked` to evict/revive
an existing owner. A rejected or revoked existing owner stays rejected. Further errors retain
the same cold preparation; only the first genuine mount owns its new lifetime.

This preparation implements Some(1) from the actual selected source. It may finish only the
exact source-bound original pin/head candidates under a distinct cold-Initializing role. It
does not manufacture a warm SavedHead/current-writer proof or resample/seal a replacement
genesis. Root supplies the actual cold repair/head receipt after its real barriers. Missing
seed with row1, a foreign stage, or a newer head remains held; SourceSaved alone is insufficient
to recreate an interrupted activation intent.

The pre-receipt physical read itself needs a TASK-FREE private read-only row1 admission and
existing-directory guard borrowing real Runtime. It checks exact unowned lineage before Root
opens the files, but authorizes no mutation. It cannot require the task, SavedDirectory or
scope preparation which its resulting cold receipt will later justify. Factory's subsequent
from_cold_activation claims its own task under rechecked same row/source. The post-read resume
repeats actual Runtime and full artifact checks before creating the new owner, so no read
result can adopt a replacement row across an unlocked gap.

The receipt's permanent validator binds physical source/read/seed/directory identities, not
perpetual scope-owner absence. Scope separately checks no owner before cache/insertion, then
the SAME newly cached owner on retry. Otherwise a valid receipt would reject immediately after
its own issuer installs the owner, or require an unsafe owner-absence bypass Boolean.

## Separate cold Current2 reader

The existing `V2CurrentPreparation` permanently records its original Initializing1 basis.
Pretending a persisted Current2 is that basis would weaken both scope and Root's Init1-only
canonical writer installation. Use a distinct `V2CurrentReadPreparation` instead:

```text
resume_v2_genesis_current(
    actual SourceRef, actual Root ColdV2GenesisCurrentHead,
    actual Factory cold-current group task,
    &mut Option<V2CurrentReadPreparation>, same-pool scope buffers
)
```

Root's new receipt proves the exact generation1 head, immutable group pin, complete source,
actual App metadata, no unknown successor/stage and file/parent barriers. The FIRST cold
Current2 implementation requires complete seed-present + pin + head + no stage. A missing
seed is not a boolean fallback in the old warm SavedHead validator. Seed-absent settled Current
is a THIRD distinct closure and stays unsupported until Root designs its actual proof; the
eventual owned Current handoff cannot silently delete its only repair source in the meantime.
Each supported role must be an independently verified complete cold Current closure.
Its pre-receipt read likewise uses a distinct read-only Current2 Runtime borrow, never an
Initializing or vacant permit. A newer head refuses genesis restore rather than rewinding it.

The scope reader requires exact Current/revision2/source nonce/provenance and NO runtime owner
or foreign group row. It caches its actual row2 preparation before inserting a NEW mounted
owner; the preparation records Current2, while Some(1) remains the historical source plan.
It has no head callback and never updates row phase/revision. Root needs a distinct paid
canonical `prepare_current_read`/Current-owner installation role accepting this exact private
preparation and the real cold head. It cannot use `PreparedV2WriterRegistration::prepare`
which currently requires the real Init1 preparation and saved activation Arc.

Only after the actual new writer is installed and complete cold head/source checks succeed
may scope bind the same row2 owner and retain its complete paid writer observation. Both warm
and cold bindings can use the existing `V2CurrentBinding` wrapper; no cold parser constructs
one. A dirty latest table, if caused by an actual same-process failed unrelated write, is
resynced with fresh quota and the same serializer, followed by complete proof/negative checks.
No row1 permit, source-write arm, SDK creation debit or old watch is recreated.

Root's512KiB metadata invoice must include the actual new preparation/receipt/observer layouts
before allocation; its separate scope allowance remains `4*(32MiB+40)+256KiB`. Each cold reader
and SDK decode has a NEW independently paid admission. Neither restart nor a scope retry
refunds/reuses an exhausted large source-write arm. Genuine crash/reopen tests must cover row1,
row2 before seed settlement, row2 after exact settlement, revoked/live-owner refusal, wrong
nonce/attempt/revision/foreign signer, unknown stage and newer head; unchanged other groups
and actual file/source/SDK fee drop order remain assertions.

## Implementation ownership and immediate dependency

Scope owns the new private child/issuer/read roles and focused tests. Factory owns actual
namespace task/guards and independent cold own-directory construction. Root owns all physical
seed/head/pin readers/writers, cold receipts, unique canonical writer installation and the
owning capsule/Current handoff. No existing Root draft, store.rs or physical namespace file is
changed by this proposal. The smallest implementation packet is the warm scope tests paired
with the actual first task, followed by row1 resume and then the distinct row2 reader after
those exact Root receipt APIs land. Do not declare the child in production or claim Current
readiness from the unpaired drafts.
