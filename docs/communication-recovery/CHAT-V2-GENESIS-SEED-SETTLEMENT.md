# Genesis activation-seed settlement and settled cold Current2

Status (6 November): connected library implementation passed actual-diff adversarial review,
production compilation and13 genuine Windows regressions. The actual warm/cold owning wrappers retain one private cleanup worker
and expose one finite `retry_seed_settlement` operation. Scope supplies the even-clean
covering barrier; Factory supplies distinct existing-owner cleanup/read guards; the physical
worker removes only its original activation seed and retains ambiguous progress. The separate
Windows seed-absent reader landed in `ad10e8cd`. This cohort adds eight warm, two cold and three
Windows Scope tests, all passing; one explicit non-Windows refusal regression remains unrun
on this Windows desktop. Strict whole-root all-target/all-feature Clippy passes. Complete
root/native suites and the deferred heavy cases remain outstanding. No later-head, live SDK,
governor or native claim.

## Actual present boundary

`persistence/cold_source_read/v2_genesis_activation.rs` writes `activation.seed` BEFORE
Initializing1 and retains its actual File in `SavedV2GenesisActivationSeed`. Its
`SavedV2GenesisHead::validate_under_archive_root` deliberately requires that same named seed.
The owning warm `genesis_seed/current.rs` validates the same node/SDK resources, scope2 and
writer, then moves them into `UnexposedV2GenesisCurrent`. Its separate optional cleanup state
retains the actual prepared/saved phase without moving the node or releasing supporting fees.

The separately paired cold capture selects actual seed+pin+head, authenticates their exact
SourceSaved bindings, synchronizes their original Files/directories and issues NEW cold DATA
receipts. Its closed `ColdSeedSelection` distinguishes actual original presence from latched
genuine absence, with independent pin/head authentication in the absence branch. Neither old
seed-present full validator can be reused unchanged after unlink. SAME-mount cleanup uses its
new cached proof; a NEW-mount cold capture independently selects its own absence proof. No
absence means vacancy or reconstructs a warm Saved receipt.

Standalone `GroupPinData::decode_data/open_pin_data` and `GenesisHeadData::decode_data/
open_head_data` already enforce the source, complete signed representatives, genesis image,
generation1/no-parent/founder-genesis kind, current revision2 and actual pin-frame ID. These
DATA decoders can authenticate a settled capture independently of an activation seed; they do
not create warm Saved receipts or choose a source by labels.

`source.seed` is DIFFERENT: bootstrap_source_work retains this large original repair copy in
the signer target alongside `origin`, `source.bin`, `records.bin`, `manifest.bin`. Settlement
touches NONE of those files, the immutable SourceSaved debit/terminal, root markers or group
pin/head. Only the original group `activation.seed` may be unlinked. The permanent g-directory
stays forever and continues the any-signer v1/v2 negative fence.

## Necessary new scope barrier

`open_chat_admission_inventory` authenticates/loads `chat-admissions.bin` but does not capture
or resynchronize its original File/parent. `resync_v2_current_scope_inventory` is intentionally
DATA-only and flushes only a dirty latest table. A newly loaded clean Current2 is therefore
not a new covering durability receipt for seed removal: a process restart may still observe a
rename whose parent barrier failed. Unlinking its repair seed before a new covering barrier
could permit a later power failure to restore Initializing1 with no seed.

Use the already paid synchronous scope writer for one explicit covering write of the SAME
latest loaded table EVEN IF CLEAN, preserving all unrelated rows. Reserve the existing
134,480,032-byte temporary credit outside writers. No row/nonce/owner/phase/revision is changed,
no disk table is reloaded, and no persistent SDK/source allowance is reset. This is not another
scope grant schema. The original owner/source/node/writer must be live before first settlement
admission; generic DATA maintenance remains independent and cannot issue this admission.

Keep the SAME admission writer held from this successful file+vault-parent barrier through
the concrete settlement callback acquiring pins -> canonical -> Root. That physically prevents
another latest-table change before cleanup; no new global revision stamp or cached clean flag
is substituted for the covering barrier. The caller repeats original row2/owner/binding and
all source/node/writer negatives after the write. Existing32MiB synchronous-I/O fairness stays
an explicit separate limitation.

## Owning settlement flow

Only Root's actual owning unexposed warm/cold Current objects may start settlement. A private
closed borrow over those actual types proves node phase (inputs/parts consumed), SAME private
SDK seed/read/resource identity, original task, actual Current2 binding and SAME installed
writer. No public trait, raw SourceId, parsed phase or caller-provided node is an issuer.

Prepare and retain `PreparedGenesisSeedSettlement` OUTSIDE all writers, in the SAME owning
object before any effect. It owns a separately prepaid metadata class, actual original seed
File/id/complete ciphertext, independent original pin/head selection and the exact source/
scope/task/writer association. Its seed-independent physical closure is prepared before
unlink, never reconstructed from absence. It may keep the original warm/cold metadata Arc as
paid identity/custody only; it must never invoke its seed-present full validator after unlink.
No SDK graph, T/R/Clock, signer, page, pin, head or ciphertext candidate is recreated/resealed.

Proposed actual roles:

1. Scope's `DurableGenesisCurrent2SettlementAdmission` is issued only after the real covering
   latest-table write above, borrowing that SAME held Runtime and original owning Current.
2. Factory's `GenesisSeedSettlementOwnerNamespace` takes pins/canonical and requires exact
   task/owner handoff, original installed writer and existing group/source namespace. It has
   no head writer/owner-replacement method. Root then acquires its original mounted Root.
3. Root's `SavedGenesisSeedSettlement` is issued only after actual unlink+group-parent barrier
   and the last seed-independent source/pin/head/ID3/directory proofs. It binds that exact
   owning node/source/scope/writer and original selected pin/head, not decoded generation1.

While all original serializers are held, compare original seed bytes+held/name identity,
independent pin/head bytes+IDs, absent head.stage and supported fixed inventories. Authenticate
all actual source/public genesis references. After every account/full comparison wait, repeat
source controls then full ID3, final group/target/name identities and closed negatives. Admit
the exact cleanup before calling remove_file; retain its private in-process progress before
the syscall. This is one fixed-name delete under the existing cooperative private-directory/
OS-session assumption, not hostile-filesystem atomic unlink-by-handle.

Unlink only that original activation.seed. Synchronize the SAME held group directory and
recheck original root/group/target/pin/head and seed absence. Cache the actual saved settlement
result in its retained owner BEFORE any later fallible return/cleanup, including post-syscall
errors or lost callback results. Private phases distinguish original-present, unlink outcome
uncertain, absence observed/parent pending, and saved absence; no decoded flag enters them.
If the original seed remains, retry only its same id/bytes. A foreign/reappeared/partial seed,
changed head/pin/private debt or later head is preserved/refused, never removed by a label.
The owning caller dispatches by its actual retained cleanup phase BEFORE invoking any old
seed-present SavedHead/ColdHead validator. Otherwise an unlink/parent-sync error would strand
the very state retained to repair it. The independent closure and phase are installed in the
same owning object before the first delete; neither a NotFound error nor a decoded status can
construct an admitted cleanup phase. A covering scope-write failure may first run the existing
DATA maintenance repair, then must perform a NEW successful even-clean covering barrier before
cleanup; it cannot reuse an earlier cached clean observation.

After successful settlement, the owning wrapper changes to a distinct seed-independent proof
branch. Scope's new settled Current2 read admission checks the SAME actual row/owner/binding
and the opaque saved settlement association; Factory's new read-only settled namespace checks
the SAME task/writer and physical closure. Do NOT weaken existing SavedHead validators with
an optional-seed/missing-file mode. The new validator must work on the same SDK/node without
new Source/Runtime/Fresh capture, and must again refuse dirty/stale/revoked final output.

The first implementation need not continue an old queued cleanup after its owning node/source/
mount is cancelled/dropped. It may retain DATA, but cannot acquire a replacement activation or
return Current. On full Drop/crash, the NEW-mount classifier below recovers either supported
seed-present or complete seed-absent Current2. This avoids a second cleanup-debt authority
while preserving progress. An exact parent-sync retry on a still-owned original attempt uses
its already-admitted seed-independent state, never the old named-seed validator.

## New-mount settled-genesis capture

Perform independent paid SourceSaved read+closed SDK restoration using the existing real
loader and original stored limits. This is a new resource debit, not SDK creation/Fresh,
source execution, KP, nonce or counter renewal. The SourceSaved/S0 read is historical DATA;
it becomes a Current candidate ONLY after actual current-head selection below.

Under the real unowned Current2 read admission (NEVER Initializing1), classify activation.seed
with symlink_metadata. Genuine absence selects the private latched Absent branch of the actual
`PreparedColdV2GenesisCapture`; any present object selects the seed-present handler or refusal.
A seed-present parse/proof error
MUST NOT be caught to try settled genesis. Once selected, the capture's role latches; seed
reappearance refuses and cannot retarget that original object to another closure.

Select/retain original group+target directories, pin and head Files/frames before authentication
or sync can fail. Decode pin/head independently with actual SourceSaved expectation and exact
public genesis representatives. Require exact supported generation1/no-parent/epoch0/sole
founder/empty acceptance/image, pin-frame ID, full source/terminal/debit/marker/nonce/limits,
and actual Current2 row basis. ANY head.stage, later/unknown/malformed head, missing pin/head,
partial/unrecognized essential source or private debt refuses with all files unchanged. S0 is
never selected merely because current-head parsing failed.

Preserve the two explicit opaque physical closure forms: SeedPresentCurrent2 and
SeedAbsentGenesisCurrent2. Root may share a private seed-independent pin/head/source core and
use a closed internal enum constructed only by their distinct actual handlers. No public
optional seed/boolean/payload constructor may authorize omission. This can keep the existing
opaque cold CurrentHead interface for Scope/Factory exact Arc/basis comparisons, without
reconstructing Warm SavedSeed/SavedHead. Initializing1 keeps its separate mandatory-seed proof.
No ActivationSeedId is fabricated for the absence variant: that getter is presently test DATA,

target has origin, source.seed, source.bin, records.bin, manifest.bin, head.bin. A head.stage

and is NEVER an alternate current source. Current approved producers write no later mutable
private state; future producers must declare their fixed debt/head/layout before side effects.

## Concrete private API

The implementation uses these closed boundaries; none is an external issuer from parsed DATA.

* Root defines a NON-generic opaque `GenesisCurrentOwnerRef<'owner>` closed Warm/Cold borrow over
  the ACTUAL `UnexposedV2GenesisCurrent<T,R>` / `UnexposedColdV2GenesisCurrent<T,R>`. Only those
  owners construct it. It exposes their same node-backed SourceRef, task, actual scope and
  installed writer negatively; no trait, SDK getter, transport extraction or caller node.
* `PreparedGenesisSeedSettlement::prepare(store, owner_ref)` reserves/checks its exact
  metadata invoice outside writers and caches original seed plus independent physical proof.
  Preparation returns owning state to be cached before I/O; a refusal leaves the old owning
  Current unchanged. The eventual owning wrapper's `retry_seed_settlement` borrows this state
  mutably, so every effect/error remains in the original owner. It never consumes that owner
  into a fallible operation that could drop its sole node/T/R/resources.
* Scope's `with_durable_genesis_current2_settlement(owner_ref, prepared, scope_buffers, rng, callback)`
  accepts only the closed real ownership borrow. It obtains Runtime, validates same row2,
  binding/owner/writer/source and clean inventory; flushes the same latest table EVEN CLEAN;
  repeats those negatives; and calls an HRTB callback with
  `DurableGenesisCurrent2SettlementAdmission<'writer>` plus the SAME mutable prepared worker.
  The borrowed admission cannot escape
  or release Runtime. It exposes source/task/owning scope association and the SAME filename
  association, not a standalone durable boolean or raw Runtime.
* Factory's `store.lock_genesis_seed_settlement_group(&admission, &resources)` obtains pins and
  canonical, confirms the actual same owned task and installed warm/cold writer via a closed
  family-specific verifier, then obtains the original Root and returns the distinct cleanup
  group guard. This role cannot install a
  writer, write a head, adopt an unowned row or renew an activation. A read-only settled proof
  role is distinct from this effectful settlement admission and from existing seed-present
  Init1/Current2 guards.
  `resources` is a SAME immutable paid Arc loan cloned outside admission. The guard borrows
  it through all selector/File cleanup while the worker mutates only phase/saved; exact Arc
  identity is required before deletion. No sender/source graph/Store or cleanup phase is in
  the loan, and no decoded limits or paid boolean can construct it.
* Root's actual cleanup worker returns a SAME retained `Arc<SavedGenesisSeedSettlement>` only
  after its unlink/parent/final proof; before any fallible result edge, it also caches that
  exact result in its prepared owner. The wrapper's closed proof enum changes SeedPresent ->
  Settled using that real receipt. The old proof owner remains paid until all its retained
  selected files/bytes/observations drain; it is not reconstructed or deserialized.
* New-mount `PreparedColdV2GenesisCapture` accepts only actual Current2 for its private absent
  branch, with a new independently prepaid closed resources loan. Its actual selection latches
  only genuine seed NotFound; the test-only Initializing1 role remains present-only. Existing
  `from_cold_current` may accept the opaque current-head family only after both variants have
  identical real SourceRef/basis/loan/final physical checks; it must never accept raw optional
  seed fields. The actual cold task/new owner/writer/binding path can then be reused without
  a second registry or changed16-slot cap.

Both owning prepared/output Current wrappers retain their original SDK/read/source/runtime,
scope/task/writer and metadata payments through these proof-branch changes. They cancel the
actual writer/scope/task BEFORE payload drop; a saved absence DATA receipt never takes over
their lifetimes. Final drop/refund still precedes the last positive proof or follows only the
infallible ownership move. This keeps settlement from silently replacing the real node with
an independently restored or merely label-matched graph.
