# Linux fixed-folder inventory (13 November; execution pending)

Genesis seed settlement, Initializing repair, pre-Initializing recovery and text
promotion previously refused Linux. Linux test successes in those areas could
therefore establish early refusal but not the complete positive warm path. The
Windows reader and its pinned standard-library invoice are unchanged.

Linux now has a private fixed-buffer reader using rustix1.1.6 RawDir/getdents.
The dependency already existed in both lockfiles; App adds an explicit Linux-only
fs edge. The reader independently opens `.` relative to the actual retained
File with DIRECTORY/NOFOLLOW/CLOEXEC, checks its identity, and borrows an8192-byte
buffer. A dup/try_clone is forbidden because it would share enumeration offsets.
Names are borrowed CStr bytes. There is no name/path vector, normalization,
recursion, growing buffer, opaque libc iterator or error fallback.

The complete expected-name specification is checked before opening: at most ten
unique nonempty leaf names. Work is bounded by the expected count plus two
optional unique dot entries and one extra-entry/EOF observation. Unknown,
repeated, missing or oversized entries and every syscall error refuse. A nofollow
stat validates every known entry, including DT_UNKNOWN. Only explicitly named
text.pages may be a directory; every other expected slot must be a regular file.
All callers pass the original held group/target directories. Original named
identity is proved before and after enumeration. These negative comparisons
supply neither cleanup nor source, writer, SDK or membership authority.

The existing actual genesis fee includes a separately named Linux buffer/layout
invoice. Promotion runs under its actual16MiB active-work debit. Static bounds
include buffer, RawDir/entry/FD, three overlapping Stat records and fixed wrapper
scratch. This accounts application overlap, not kernel/native heap/RSS. Other
platforms keep the explicit unsupported-profile refusal before effects.
