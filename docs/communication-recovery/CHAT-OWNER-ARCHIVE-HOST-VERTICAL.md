# First actual private archive host (design; not implemented)

This is the next consuming integration, not another public authority API or completion claim.
The reviewed page/chunk/node/manifest/record codecs do not mount ARCHIVE2, write a covering
canonical head, restore a current owner or activate Chat V2. Do not accept the namespace before
its complete fixed-name inspection, journal repair and actual original-source consumer exist.

## Concrete current seams

* `ServerStore::private_managed_founder` performs actual synchronous founding and captures its
  original physical mount and logical admission before exposure. Its private `Server` cannot be
  extracted through a public raw snapshot/creation-label constructor.
* `PrivateManagedServer::reserve_scope` retains the original Fresh attempt and exact reservation
  across errors. Staging that SAME private scope before `prepare_owner_v2_founder` is mandatory;
  unmanaged preparation followed by a different reservation cannot rebind the frozen source.
* `ChannelSync::prepare_owner_v2_founder` and `FrozenFounder::borrow_for_covering_save` derive and
  recheck actual original creation/scope before yielding Profile/Admission/header/state DATA.
* Existing `freeze_for_owner_initialization`, canonical `Meta`, saved tokens, root pin installers
  and restore parsers consume the finite v1 checkpoint. They are NOT generic V2 consumers. Do not
  widen their exact format gates or supply a fake v1 evidence tail to release a V2 owner.
* Canonical writer serialization already uses original admission -> head custody and a single
  revoking owner. V2 must preserve that physical per-group/full-signer exclusion across numeric
  aliases. A second disjoint V2 writer map must not allow concurrent old/new protocol owners.

## Actual first vertical

Implement an explicitly configured private V2 host, without switching the native product on.
It must found an actual group, retain a real signed action, append its actual acceptance under a
V2 signed header, cover the exact result and original bytes, survive interrupted writes, and cold
reopen through the supported mandatory critical namespace. A bounded paid privileged reader must
return the exact retained original with explicit completeness. This establishes ONE real source
path; it does not establish mixed-member V2, Add/Remove/join/Review, network catch-up or rollout.
Those are subsequent consumers of the same storage invariants, not reasons to enable this slice.
Independent design review found and resolved the original pre-source scope-row and partial-write
retry holes below. That is architecture review, not implementation or crash acceptance evidence.

Creation must prepay actual host/source/archive buffers BEFORE actual MLS founding or public
record preparation. Existing founder64KiB and ReplayMath1MiB are named logical layout invoices,
not actual leases. Existing checkpoint SDK limits and default CatalogReadPool are not an implicit
V2 budget. The configured policy must name separate ordinary, required-control, read, persistent
file/byte and private SDK-candidate allowances, each backed by the real shared account/owner.

The actual private host retains, in destruction order: frozen private/provider and public-page
candidates, exact pending write result/negative observers and writer, then their original fees.
It owns no generic `Server` escape, `saved=true`, copied runtime owner, raw-current snapshot
initializer or arbitrary-path sink. Initial scope, creation, pin and writer must remain the SAME
actual source through all signing/snapshot/storage effects and final Current install.

Before first scope-row mutation, persist a small typed **V2 FoundingIntent** under the supported
original archive namespace. Its trusted producer owns the actual private Fresh source and RAM
reservation; the record binds original group/full signer/attempt, Profile/genesis, exact expected
vacant scope lineage and planned next nonce/revision. It grants NO recovered Fresh/current source.
The metadata write is admitted under the original capture; a public decoded copy cannot mint it.

This first vertical chooses a dedicated **V2 unexposed-negative recovery** for a crash before any
complete S0 exists, rather than claiming lost SDK state can be recreated. It may retire ONLY the
exact FoundingIntent's Initializing row, after bounded complete inspection of BOTH protocol head
namespaces, canonical and stage, journal/seed/publication records, pin and actual scope lineage
proves there was no exposed/saved source. Missing/unknown/foreign essential metadata refuses,
not absence. The negative transaction retains the original intent/evidence and cannot touch a
different nonce/revision, Current, existing head or a later creation. It creates no publisher,
Fresh proof, positive restore or new retry allowance. This is a NEW V2 adapter; exact-v4 S1 and
existing source-absent paths stay unchanged. Bootstrap crashes resolve automatically as an
unexposed failed creation; they do not leave a phantom open group or invent another founder.

Order for first creation:

1. Prepay; perform actual private founding; capture its exact RAM scope plan; durably persist
   the typed original FoundingIntent BEFORE installing its exact Fresh Initializing scope.
2. Stage that same private scope/reservation; prepare/freeze actual V2 public genesis once.
3. Prepare the private genesis record batch, exact encrypted page and immutable manifest once.
4. Freeze actual bounded SDK/server S0 under a V2-specific original-source validator. The old
   checkpoint snapshot method cannot stand in for this. No incoming run/subscription is allowed
   while constructing this private candidate. Retain actual provider bytes and their own fee.
5. Under original scope -> unified logical head custody, prove exact initial absence, durably
   install the immutable V2 profile pin and complete pending source, then write/sync all children.
6. Save the new canonical head with its exact manifest and private SDK source references, cross
   required file/parent barriers, install Current, and return only an actual bound V2 host owner.

No new public proof is exported before step6. An error preserves the complete exact candidate;
retry cannot reseal pages, regenerate a Profile/Admission/header, resample a private snapshot or
substitute a fresh source. Source retirement cancels positive work before waiting for writers.
Once a storage operation was admitted, close completion waits for its actual synchronous result.

## Namespace and canonical source

Critical namespace ARCHIVE ID2/version1 is a small immutable descriptor, at most4KiB. It fixes
the original physical layout and per-group fixed head/journal names; it contains no peer/caller
path or changing per-message roots. Its declaration is a rare monotonic catalog change. Ordinary
messages do not rewrite the unrelated JOIN1 payload. Unsupported readers refuse current OR
stage before older cleaners. Root/catalog provenance must survive the original mount, not an
equal physical path reopened after an await.

The V2 canonical head must have a distinct strict tag/version. Its complete sealed-frame digest
has its own domain and is the `ArchiveHeadId` in the NEXT manifest. It references this operation's
sealed manifest PageId, signed public-header/state identity, original group/full signer/Profile,
scope nonce/revision and CURRENT private SDK source. The manifest references the PREVIOUS head,
never its own new head. Historical manifests never retain every superseded secret SDK snapshot.

Existing root pins, canonical metadata/runtime slots and source inventory need explicit protocol
kind discrimination: a raw `OwnerFactId` alone is not that discriminator. BOTH existing v1 and new
V2 disk namespaces must be inspected before any v1 absent-source initializer/restore can proceed.
An unrecognized or conflicting existing V2 source reserves the logical group negatively. Old-format/
v1 head parsers must refuse the new head, not treat it as absent or initialize another owner.
The unified runtime writer slot must distinguish formats but keep the same original
group/full-signer exclusion. A known pin or unknown existing head reserves the namespace negatively;
neither can create a Current writer before complete source validation and real file barriers.

## Exact journal and crash order

There is one fixed per-head pending journal plus its fixed stage, with a distinct strict domain.
Authenticate/parse BOTH complete sources before settlement. Only an exact whole-plaintext duplicate
or exact known successor of the same original parent can be resolved; matching one field or one
candidate page is insufficient. Unknown/partial/foreign sources remain retained and closed.

The journal keeps complete original sealed archive candidates (<=3 content pages+manifest), the
exact original parent/new-head identity, operation/bindings, original allowances and execution
consumption. Its512KiB archive-candidate cap does not include or replace separately paid exact SDK
snapshot/Welcome/reply/publication bytes. Those need their own retained sealed candidates and
covering child references. A digest of absent private bytes cannot repair their effect.

Before any dependent child write, the original durable journal must name all candidates. Each
child is immutable under its complete ciphertext ID. Use create-new, never truncating overwrite
or generic BlobStore stage cleanup. Exact existing ciphertext is resynced. A short-write prefix
has one narrowly defined repair: a COMPLETE independently authenticated original journal/seed
must supply the exact expected sealed bytes and ID; under the same original pinned parent and
head/scope writer, open the existing regular singly-linked file without following redirects,
hold its actual identity, and compare its complete current contents with that expected prefix.
Only that exact SHORT prefix may receive the SAME remaining bytes through the same handle,
without truncation/resealing. Revalidate actual destination identity and final whole frame/hash,
then cross file/parent barriers before CAS. Non-prefix, oversized, foreign, redirected, replaced
or unsupported sources refuse/preserve. A generic hash mismatch is not a repair permission.

The fixed journal itself has a separately paid **immutable exact seed copy**. Its COMPLETE
authenticated bytes, original parent and candidate bindings must be durable before creating or
changing the fixed journal. Keep the seed through journal/head/child/debt barriers; it supplies
the exact original frame for warm OR cold prefix completion of a short journal write. The same
whole-source stage/current rules apply; a matching subpayload is insufficient. The extra seed
file/frame/read/compare/repair capacity is an actual separately enumerated fee, not borrowed from
the four archive candidate pages or their512KiB cap. A partial/unknown seed that supplies no
complete exact original cannot authorize repair. During bootstrap it blocks only its original
unexposed source and the new negative adapter must prove its own full absence obligations.

Private work can begin only under an actual persistent original operation grant with spent
execution counters. Preparing or retrying the seed cannot mint/refund those counters. A proven
unstarted seed preparation may be negatively resolved only by its separate exact original grant
transaction; an ambiguous admitted operation stays retained. Those grant/negative codecs and
consumers are prerequisite implementation, not an allowance inferred from the journal layout.

Parent-head CAS occurs only after actual child/file/directory
barriers. Clear debt only after the exact covering head and required parents are durable.

If disk still has the exact parent, validate the complete original candidate, obtain actual hot
fees, restore spent execution state and finish that same CAS. If the exact candidate is already
canonical, validate/resync its actual child closure and settle that same debt. An unrelated head
cannot be adopted by matching group labels. Restart is not a fresh execution/retry grant.

Initial inspection has its OWN paid bounded raw/unframe/plain allowance before decryption. A
journal cannot pay for its first read merely by containing allowance numbers. Page/raw/cipher/
plaintext and journal-copy capacities, not just lengths, must be enumerated at actual call sites.
The whole scalar/typed SDK allocation bound remains a separate prerequisite; raw provider bytes
alone do not bound expanded OpenMLS/serde objects.

## Retain, accept, read and partial availability

Separate retention from acceptance: retain the exact signed original action under a covering
manifest first. Only then can a real finalizer append its AcceptanceRecord, complete nodes and
signed header/body/state batch in one new governing transaction. The first vertical may use the
actual founder's own admission only; it must not accept raw Grant/Basis labels or public math as
ordinary/action-specific authorization. Duplicate acceptance requires exact complete-prefix lookup;
an in-memory map with a lifetime entry limit is not a scalable substitute.

Restrict the first action consumer to **Create by the actual current founder**. Its private host
derives realm/grant/basis/subject from its original Saved V2 source and exact selected Admission;
it verifies the actual signed action against those internally derived values and the supported
ordinary rights. No public caller-supplied rights, generic verifier callback, Profile/self-signature
or ReplayMath object can be wrapped as `VerifiedAuthority`. Edit/Delete/review and other admissions
remain refused until their own complete dependency/acceptance/approval consumers exist.

A bounded reader captures an exact finite manifest prefix and advances paid reconstruction turns.
New appends do not restart that prefix. Missing/reconstructible indexes are incomplete, never an
empty complete ledger. Requested originals require manifest/ciphertext/inner context/digest and
actual signatures before typed output. Native moderator authorization remains a separate actual
lease; the archive reader cannot expose a generic decrypted-provider/page/path command.

Essential governing/key/negative closure precedes positive exposure. Missing historical body chunks
only pause dependent audit/effect work and trigger bounded exact repair. They cannot erase Delete
custody or block independently proven control/other-group progress. Ordinary operations must not
spend required control memory/files/journal/sequence capacity. Both public and PRIVATE manifest
sequence exhaustion require admission planning, not unchecked wrap or a larger timeout.

## Required adversarial evidence before this consumer is accepted

Use real creation, signatures, typed bodies, private SDK snapshot, actual Store files and barriers.
Test pre/post journal rename, child/file/parent sync, canonical head rename, scope Current write,
real partial first seed/journal/child writes, exact-prefix and foreign-prefix identity races,
retirement between each admission boundary, exact same-process retry and cold original-candidate
recovery. Test old authentic wrapper/unknown catalog/current+stage combinations before old cleaners,
foreign original mount/group/signer/pin/parent, same numeric aliases and same-key lock/unlock cycles.

Then retain/accept/read a real action, deliver genuine alternate signature representations, reopen
without a fresh KP/header/nonce, corrupt/remove one old audit chunk, and demonstrate truthful partial
history plus independently proven progress. Verify source/fee custody survives queued lower copies
and caller cancellation. Required-control work under ordinary byte/file/sequence saturation and a
second group under sustained bulk work need actual scheduler evidence. Codecs/model tests are
not substitutes. All compilation/tests/builds remain paused by the user while source work continues.
