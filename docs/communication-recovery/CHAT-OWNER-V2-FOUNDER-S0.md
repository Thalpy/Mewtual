# One original V2 founder private S0 (5 November; authored, unexecuted)

This is a private consuming DATA prerequisite for the future
[archive host](CHAT-OWNER-ARCHIVE-HOST-VERTICAL.md), not an App saver, positive restore or activation.
It must not widen the finite v1 checkpoint format/Saved/Current path. The actual original physical
Fresh and scope observations already owned by `FrozenFounder` remain the only preparation source.

## Concrete API and original-source order

Add `FounderSnapshotLimits` with private fields and checked constructor for maximum complete Sync
snapshot, MLS snapshot and physical provider-table backing. The closed S0 ceilings are8MiB MLS,
8MiB backing and8MiB+64KiB enclosing snapshot; these are initial never-run source limits, never a
lifetime history/member/log cap. Zero/above-ceiling/overflow and MLS+existing64KiB metadata greater
than enclosing cap refuse before any encoder. Checked provider payload allowance is2*MLS under
the existing local capacity policy, not an SDK guarantee. Getters expose inert quantities for a
future actual host admission; none reports paid/reserved state.

`FrozenFounder::cache_private_snapshot(&mut self, &mut ChannelSync, limits)` first repeats the
same actual original Fresh/scope/untouched/full public record checks as its public DATA borrow.
The exact private staged Active scope must already have been captured before prepare/freeze;
an unmanaged object cannot be rebound now. This slice additionally requires the existing closed
initialization snapshot shape. It then calls `snapshot_owner_initialization` internally, reusing
only that encoder/preflight after the stronger actual V2 source validator. It attaches no v1
owner tail and creates no v1 Saved token. Immediately after capture it repeats original checks,
including the same negative observers and exact immutable Profile/Admission/header/state.
The stricter S0 shape requires `member_finalization_pending` empty, so the shared encoder's
finalization-pruning step cannot change this private source while capturing it.
Only then does it cache one `Zeroizing<Vec<u8>>` plus the exact limits and typed S0 digest.
Errors drop incomplete private bytes and preserve the original public records/observations/cache.

`borrow_private_snapshot_for_covering_save(&self, &ChannelSync)` repeats actual original checks,
requires the cache and returns a borrowed private DATA view containing exact bytes/digest/limits.
The digest hashes domain `mewtual/chat/founder-s0/v2\0`, original ProfileCID32 and COMPLETE raw
snapshot. It is not a ciphertext/page/head/public-state ID, source, key, Saved or Current witness.
No mutable bytes, Server/device/transport escape, generic source setter or snapshot-to-Prepared
constructor exists. Debug omits the secret bytes and digest. Every public borrow continues its
original checks, independently of whether an S0 has been cached.

After one successful cache, repeated cache calls with identical limits return the SAME bytes and
digest without invoking the encoder; changed limits refuse. Plain borrow has no replacement limits.
Canceled/replaced/taken/equal-but-restored or CURRENT-mismatching source refuses with a cache present. The
cache does not keep any original Fresh/reservation sender or runtime authority alive. Under a
mutable capture call no ordinary Sync mutation can run concurrently, but external negative owners
can revoke. Pre/post checks detect that boundary; they are not an atomic publication/save lease.
Any returned borrow can outlive a subsequent external revocation. The actual host must still hold
its ORIGINAL atomic commit admission and check negatives at actual storage/export edges.

### Exact current private source comparison

Fresh/epoch/scope alone do NOT prove unchanged S0 bytes: allowed rendezvous/policy/routing/key
metadata or an extra device KeyPackage can change without advancing the epoch. Before admitting
the first cache and before every later public/private borrow, compare the actual current private
source against that SAME cached S0. This never creates a replacement snapshot or updates the cache.
This is exact CURRENT equality, not a history of all mutations. Metadata changed and restored
byte-exactly before inspection may pass; permanent original Fresh/scope negatives remain separate.

`catcoms_mls::persist::compare_server_snapshot_bounded` supplies the narrow DATA comparison. It borrows the
cached MLS frame completely, then hold the SAME actual provider read guard through existing
O(1) allocation-size admission, independent retained-payload/output/count preflight and exact
key/value/count comparison. Compare complete cached storage rows to actual `map.iter()` in the
same order used by the existing snapshot encoder; no allocation/copy/sort/encoding of provider
rows occurs. Backing includes tombstones, not reported len/capacity. A changed iteration order
can conservatively refuse even if contents match; it never rewrites the original. Full signer,
group, framing and every key/value/count must match. This is not an MLS/current/fresh certificate.

The Sync comparison borrows the cached complete outer framing and compares EVERY non-MLS field
in shared `snapshot_with_governance` order against the actual closed source: bounded routing
state (compared borrowed without copying secrets); empty ledger/docs/log/peers; file-wrap key;
roster generation/empty legacy grants; all
rendezvous pairs; empty direct replies; actual tenure/policy; empty durable chat/finalization;
admin tag/empty roster; and exact local scope with no owner-v1/operation extension. Reuse the
existing individual bounded encoders for nontrivial fields, one field scratch at a time
(tenure, policy, durable chat, scope); no full second Sync snapshot is re-encoded. The empty
finalization parser already accepts max_entries0 without creating a map. Constructor caps/counts
must pass before each variable field encoder. A maintenance comment next to BOTH the shared
snapshot encoder and this complete comparer requires simultaneous updates for new fields.
Additional Sync/MLS encoder-entry observations are test-only; tests distinguish one S0 capture
from repeated bounded field comparisons. No claim of 'zero encoding work' on retry is made.

## Separate resource invoice and restore limits

The founder64KiB invoice pays only named public-record/scope/watch/signature DATA. It does not pay
cached secret S0, provider backing/payloads or encoding. SnapshotLimits does not acquire a fee.
The future host must separately retain/pay original SDK provider table<=backing + retained Vec
payload capacity<=2*MLS, one MLS encoded output<=MLS and one enclosing/cached output<=snapshot,
plus bounded metadata/routing/tenure/policy encoding scratch and public original records. The
existing encoder holds one actual provider read guard through its backing/payload/output checks;
it neither clones/compacts the provider nor claims whole typed OpenMLS/serde/allocator/RSS bounds.
One bounded metadata field scratch (at most the existing64KiB metadata allowance; policy<=4101,
scope<=512, routing<=364, tenure<=256) requires independent payment alongside the retained cache. No
full second S0 or fresh MLS output is created by exact source comparison.
During retry the cache stays retained but no full Sync/MLS encoder or replacement snapshot runs. Sealing,
file/raw/AEAD/journal/seed/head copies and cold restore/typed SDK expansion have separate invoices.

The cached S0 uses unchanged existing Sync private framing with no V2 reinterpretation. A generic
actual SDK restore may be used in regression tests to compare group/authenticator/signer data;
it restores no Fresh token and cannot adopt the original FrozenFounder. Positive archive reopen
still needs the actual future source/head/namespace/key/lineage consumer, absent from this slice.
