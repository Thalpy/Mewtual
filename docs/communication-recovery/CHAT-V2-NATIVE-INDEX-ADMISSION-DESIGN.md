# Native index admission and founder integration

Status: implementation design, following PR95's physical initial installation.
This document is not implementation or activation evidence. Chat V2 stays disabled.
The next increment must include a real owning founder consumer, not only another
generic DATA codec or a boolean authorizing a library product.

## Durable birth and compatibility

Parent hashes provide CAS ordering, not request identity. Namespace7/version1's
Pending shape loses its invocation/network association on activation. The native
writer therefore needs an explicit **namespace7/version2, index2** contract.
Namespace6 remains reserved for the joined-pin work. Existing version1 APIs and
grammars remain closed; no enlarged row or new Stage interpretation silently
reuses their contract.

Every new birth retains the original invocation (the create token), canonical
original-request digest, full signer and stable funded network identity through
Pending, Founder, Retired and Abandoned. Current mutable display metadata is
separate from the immutable original request. Same token/digest returns the
original row/status, including after unrelated index updates; changed inputs
conflict. Terminal birth records are not recycled. Lookup precedes fresh RNG,
sealing, device generation or SDK work. The caller retains its original token
before effectful dispatch.

The canonical request binds actual protocol/founding inputs and original network
configuration. It must not depend on freshly drawn AEAD nonces or values generated
again on retry. Inputs generated by the first operation remain owned/cached or are
recovered from that operation's durable birth; the retry cannot invent substitutes.
Resource-only policy changes must be classified deliberately rather than silently
changing an existing request's meaning.

Initial index2 can be declared over a private Current3/member5 mount. A separate
upgrade supports only the genuine version1 producer's **Legacy-only generation1**
state, preserving exact numeric IDs, stable identities and metadata. Later or
non-Legacy version1 state is preserved/refused. The upgrade holds exact old/new
catalog, index and marker frames in a complete authenticated seed. It uses a
durably synced **empty** old catalog Stage fence before upgrade content. A complete
duplicate old catalog is not an adequate fence.

While the old catalog is selected, only exact cached old/new output combinations
may complete under the seed. After catalog2 selection both index2 and marker2 must
already be exact successors; missing/old/foreign committed outputs refuse. The
seed must never reconstruct or roll back a promoted catalog's outputs. All file
and parent barriers and cleanup finish before exposing the opaque owner. The real
8bca2d8d version1 reader must refuse unchanged at every content-bearing upgrade
cut and completed2; a genuine version1 control must open.

## One mount-wide index serializer

One private physical owner supplies the serializer shared by all aliases. It owns
at most one prepared or uncertain candidate and its complete payment, parent File,
exact parent frame, candidate bytes, Stage handle and cached phase. Preparing an
operation reserves that cell before effects. A dropped caller cannot erase the
candidate or permit another same-parent writer. The cell retains serialized debt,
not an authentication sender or key End.

Every change names the exact original generation and preceding **framed ciphertext**
hash and validates a closed semantic successor. Birth preserves every old row and
adds exactly one unique Pending. Activation changes exactly its matching Pending
to Founder, preserving immutable birth. Retirement and proven abandonment have
their own actual source/journal prerequisites. A generic valid snapshot with the
right parent is insufficient. Legacy projection merges against the whole typed
index and cannot discard pending, active, retired or terminal birth records.

The complete authenticated index Stage can be the index-only replacement WAL.
Cache it before effects, complete/sync it before rename, and record selection
before any fallible covering barrier. Cold next-generation recovery requires the
exact preceding frame hash and semantic transition. Duplicates cross the selected
file and parent barriers before cleanup/success. Authenticated malformed, empty,
foreign or future candidates stay preserved. Unauthenticated first-torn Stage may
be abandoned only with the same continuously held Stage, durably authenticated
selected index/marker, no declaration debt and no external operation that relied
on its selection. This is not a transaction over SDK/network/source files.

Explicit invoices cover both selected/candidate snapshots, transient decode/seal
overlap, metadata, retained receipts and uncertain control state. Charge before
copying and retain payment until dependent state drains. All byte/row/counter and
generation overflow checks precede effects. These logical quotas do not claim
allocator/RSS or disk-space guarantees, nor general rollback freshness.

## Actual network reservation

`ServerNet.key_seed` determines identity; port, routes, consent, recovery fields,
ciphertext and record sequence are mutable. The stable identity commits to the
**full transport public key and key algorithm**, with a domain. The owning
reservation separately binds vault/layout, invocation and original row identity.
The concrete Mesh constructor verifies the actual libp2p and Phase-0 peer IDs;
caller-asserted PeerId DATA is insufficient.

The non-Clone, redacted reservation owns the seed-bearing input, validated bounded
configuration, first sequence reservation, exact sealed initial frame, destination
File/phase and payment. Pending2 retains that exact bounded frame until activation:

1. Lookup before generation; generate/cache the original identity once.
2. Seal/cache the initial network frame once, with its first sequence block.
3. Durably select Pending containing those exact bytes.
4. Complete the real network file from that frame with original-File and parent
   barriers. No unbounded legacy load or absent-file fallback is used.
5. Construct transport only afterward, then prepare/advance the genuine founder.

`ArchiveFounderInputs` already contains a transport and a constructed device, so
preparing that driver cannot authorize earlier input creation retroactively.
Native's original input stage must capture/gate/cache actual device generation;
transport construction cannot precede its persisted sequence reservation. A narrow
production Net adapter is preferable to duplicating libp2p identity serialization;
adding the currently dev-only Net dependency needs an explicit architecture change.

After activation, never recreate missing network state from the initial frame:
that could reset sequence reservations. Mutable network saves preserve identity
and merge the actual current row's sequence/routes under its owner. Absence,
corruption, mismatch or sequence exhaustion remains held/refused.

## Owning founder and original native commands

One concrete `PreparedNativeFounder` owns frozen original inputs, the Pending
receipt, network reservation, whole genuine fresh driver, original negatives and
payments. It cannot advance the SDK until Pending/network durability succeeds.
Activation derives its tuple internally from that same completed native operation;
no public binding DATA, ready boolean or library driver can install a backend.

A cold Pending is never another SDK grant. The existing creation journals classify
cold debit/intent/stage/seed as Existing; only the original live creator can consume
its SDK ticket once. Recovery after SourceSaved needs the genuine cold operational
owner. Until it exists, retain/hold rather than re-enter the SDK or invent Active.

Reuse the real synchronous Tauri router pattern in `admin_chat_ledger`: resolved
ACL/main surface, generation capture before parsing, original row/backend capture
with try-locks, then native-owned dispatch. An async body's first poll cannot
capture the invocation's original session. Native uses an irreversible Root
`NativeRequired` origin and distinct owning wrapper; library retry/advance refuses
that origin. Commands retain observers; only the actual native registry owns close.

Concrete key purposes include original device generation, SDK creation, initial
bootstrap profile/header work and ordinary member Drafts. Gate SDK use after the
held-file/source proofs at its actual ticket CAS, retaining End through the actual
server cache. Gate ordinary signing after selected-source/Core proofs and retain
End through raw64 cache and the outer Current guard release. Bootstrap signing
cuts still need their complete trace; entry checks cannot stand in for them.

Final native issuance checks the actual shared UI generation/request flags as well
as the immutable source/session/row/request binding. Close ordering cannot leave a
generation-published/control-still-open interval. Sequentially consistent bounded
counter admission can fence End drainage, but wakeups/destructors must occur outside
Root writers, including refusal/unwind paths. SDK consumption and Core KeyEntered/
raw cache remain once-only authorities; native counters never refund them.

UI lock closes command issuers before awaits and drains outside UI/Store/registry
guards. It retains the mounted source. A new explicitly authenticated same-token
command may reuse its retained unspent creator or cached raw; the old command
endpoint never changes session or reopens. Row/vault retirement independently
closes actual source admission before waiting for escaping loans. Phase2 immediately
hands admitted work to a native-owned worker and caches outcome before custody drains.

## Native mounted backend and acceptance

Replace the physical Store and backend together: opaque Root legacy/typed sum,
concrete common operations, genuine native backend enum and checked legacy-only
selections. No second Store, optional V2 sidecar, raw getter/Deref or generic lease
callback. Preserve old DurableSend/Shutdown constructors and add closed mounted
guard variants. Backup must freeze/drain all escaping writers before copying;
the outer Store mutex alone is insufficient.

Regressions must cover actual Pending/network/founder/activation with one SDK
admission; lost replies after each phase and unrelated updates; token conflicts;
every Stage/rename/barrier cut; aliases, owner drop, original-mount replacement and
caps; unpolled real router tasks across lock/unlock; both key/phase2 orderings and
unwind; observer survival after owner removal; generation-publication gaps; escaping
loans and backup; actual earlier-reader refusal. Complete root/native/frontend,
strict lint/audit and relevant native startup/flow checks remain required.
