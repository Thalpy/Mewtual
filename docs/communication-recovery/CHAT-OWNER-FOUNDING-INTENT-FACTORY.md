## Invocation before group creation

request DATA, not a user authorization token or a remotely supplied grant. The caller must retain

Root derives every filename DIRECTLY under the original mandatory `chat-owner-v2` root: the

No caller path is accepted. Target directories are separately derived64-hex names without suffix.
The original independently authenticated root is captured before resource/writer waits. The
full vault/root/invocation/request binding remains inside the record, not merely its filename.

The request binds the actual provided device's FULL signer, exact bounded UTF8 name (<=256 bytes), supported V2 founding kind and original
closed FounderSnapshotLimits. It does not bind later mount incarnation, random nonce, ambient
time, peer connection or a caller-selected resulting group. A same invocation with a changed

## One persistent creation unit, not a parsed counter

The immutable `.debit` grant record is already Debited: allowance1, spent1, original invocation/request
binding and original vault/root. Before the actual group SDK call, Root must
write/sync this COMPLETE exact candidate and its parent, returning a non-Clone

constructor from a decoded number/bool. The original vacant invocation capture and warm creator
identity distinguish an original uncertain-write retry from cold observation of a spent record.

Only consuming that one warm debit can enter Server::found once. Entry takes the one T/device/R/
Clock inputs from Options BEFORE calling the SDK; errors cannot run another group creation with
the same unit. Actual SDK-returned failure can prepare a negative unexposed terminal; it does not
refund the unit. The factory owns no mutable Server getter, does not call run, and performs no
networking. Exact warm retry continues the SAME creator/source; a second invocation call sees
Existing rather than extracting or reconstructing it from Store.

Cold reading Debited NEVER creates another SavedCreationDebit or invokes Server::found. It
returns retained in-progress/unknown/closed state. A new SDK attempt requires a genuinely new
explicit user invocation. There is no timer reset, silent request-ID eviction, or lifetime5-group
cap. Immutable grant lineage remains on disk. Configured bounded outstanding writes/memory may
pause new work without discarding a spent invocation. Direct per-invocation lookup and bounded
repair turns avoid loading every historical grant into RAM.

Keep heavy source I/O separate from the ONE SDK unit. The original trusted local creation policy
funds a bounded number of whole source-write passes (original allowance1..8; the actual heavy
write consumer remains unfinished). Before each pass that can write the large source seed/source/pages,
durably increment the intent's spent-I/O count under the original source ID/context and obtain
one non-Clone SavedSourceExecutionArm. The actual Root write consumes it once. A failed/ambiguous
pass stays spent; restart/another mount/caller Drop does not reset it. One pass has a closed maximum
write/read-byte inventory and returns after one bounded attempt, not an internal unbounded loop.

Small fixed grant/intent arm updates have their separate control metadata allowance; pretending
an arm write prepays itself would be circular. When the original heavy allowance is exhausted,
retain the SAME source/seed/debt and return HeldExecutionExhausted. Never create another group or
silently refill from a lookup/mount. A later explicit user retry-grant API must preserve its own
invocation/idempotency lineage; it is not enabled by a count field or this first factory. Cold
negative exact-source repair can spend only remaining original I/O units and never mints SDK/
Fresh/Current authority. No copy/RNG/SDK work is repeated when bytes are already retained.

## Lost replies, cold outcomes and negative closure

Warm I/O ambiguity retains the exact transaction/ciphertext/source, original sender and all needed
fees; retry changes no nonce/group/key/request or execution allowance. Store holds serialized debt
before mutation. Cold outcomes are explicit: ExistingDebited, ExistingFoundingIntent,
ExistingSourcePrepared (with source availability), ClosedUnexposed, or Incomplete/Unknown. They are
not generic NotFound/new-grant results. Existing encrypted source can be read through the strict
offline DATA reader; it cannot reconstruct Fresh or an SDK-founding permit.

The smallest automatic unexposed closure is negative only. A complete immutable debit with NO
intent current/stage/small-seed/later transition/debt may close only after actual known invocation
files pass barriers and the warm creator is dead (or explicitly closes before SDK admission).
Save ClosedUnexposed preserving spent unit/request/debit, never refund/restart SDK. This proves
no exposed group/SourcePrepared, NOT absence of target reservation: a crash can leave an empty
target before a discoverable invocation link. Every possible orphan target stays negatively
reserved/unknown and is never reclaimed by closure or a lifetime scan. A private source lost
before any intent successor is therefore failed-unexposed, never replaced.

For FoundingIntent, closure additionally needs exact original target/link/current and original
VACANT table/head/pin state, original creator negatively closed, and proof no SourcePrepared
current/stage/seed or large source debt can exist. Preserve all grant/intent bytes/diagnostics.
Partial/unknown stages and SourcePrepared—even when the source seed is missing—remain held for
bounded repair/unavailable-result handling. They cannot be negatively reclassified from timeout,
dead weak owner, missing old canonical file or a flag. A durable closed target remains negatively
reserved; other groups/control progress independently. Root must supply actual opaque absence/
barrier evidence; a caller boolean never closes a grant.
