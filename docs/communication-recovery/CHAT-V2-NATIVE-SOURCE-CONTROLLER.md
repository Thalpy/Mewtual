## Canonical installation

The native controller owns a removable `Option<NativeTextSources>`. Workers
receive finite captures, never an Arc to that owner/controller. A private
`ReadyBundle` pairs one actual facade with the only Sources issued by that same
facade. Installation moves both under Store then controller, after original
bootstrap-control, UI-generation, prelude and phase checks. Losing bundles stay
in an outer slot and return to the original bootstrap plan outside guards.

Root's cached original-vault comparison tests allocation identity only. It
continues matching after closure and grants no UI, key, readiness or drainage
authority. Native requires it before source capture, metadata/UI capture and
final paired removal. Foreign/missing replacement state retains the original
obligation; an empty replacement cannot certify an earlier close.

This intentionally strengthens the earlier snapshot-only close contract:
acknowledging a foreign screen-state loss still avoids writing either vault,
but cannot permit destruction while the mounted facade and original Sources
disagree. The original pair must be restored before its shutdown can complete.

Actual bootstrap file work has packed CLOSED/count admission (one position).
Admission follows prelude-idle/original-generation checks, immediately before
taking the original plan. `BootOutput` exists before scheduling and owns the
plan before its End, covering unpolled closure destruction, unwind and returned
output. The End remains until canonical transfer or actual destruction; it does
not span unlock's finalizer. Zero does not dispose a parked partial plan.

## Close order

Tentative close permits reauthentication when continuity defers destruction.
Irreversible closure starts after `may_destroy`, final UI-key retirement and the
existing history freeze succeed. Thereafter unlock refuses, including when
later close work needs retry.

1. Close original bootstrap admission and await actual boot Ends.
2. Take/drop retained partial or uninstalled bootstrap outside guards.
3. Capture the same Sources under Store/controller. Finish and execute finite
   SDK/body retirement on the blocking executor outside guards. Pending retries
   use the Clock seam. Root separately proves key, SDK destruction and TCP ends.
4. Drop the actual retirement capture. Capture original metadata/UI work from
   the same facade and await its exact capsule acknowledgements outside guards.
5. Recheck original pairing, take both owners, drop Sources then facade outside
   guards, and publish Disposed only after actual destructors return.

Close never joins `vault_mount` or the whole unlock/IPC task: unlock may own that
mutex while awaiting close's prelude. Lost close work leaves canonical Sources
and Root evidence for exact retry, with no failed-task/idle-counter shortcut.
A destructor unwind cannot publish successful disposal.

The independently paid boot control is the last controller field and has no
owner/key/Store/physical backlink. The invoice includes controller, ReadyBundle
and BootOutput overlap. Root separately funds its own source/runtime/transport
and work-retirement objects. Source helpers still drop completed index debt
before returning; metadata/UI zero alone is not universal physical release.
