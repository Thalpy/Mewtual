# Founder-only V2 acceptance and signing boundary

This library slice supports the sole founder at epoch zero, repeated Create without reply.
It does not enable multi-member text Chat V2. Production operational storage, membership/
epoch governance, transport/native ingress and complete audit composition remain unfinished.

`V2FounderExpectation::from_trusted_host` is explicit HOST trust configuration. Its complete
group/founder/Profile/Admission/tenure/genesis Header/state tuple must come from the actual
independent root pin and covering source receipt. Incoming self-signed records must never
select their own expectation. Core verifies each actual signature and complete genesis
body/image, retaining a bounded `ReplayMath` cursor; no hot-snapshot initializer exists.

Cold verification has a separate opaque, nonissuing `V2FounderReplayCursor`. It starts
at that same fully authenticated genesis and verifies each Append with the existing
signature/lineage/image/math checks. It cannot issue semantic authority, projection
support, a signing permit or an active candidate. It needs no premature writer/Scope
owner; the physical host still funds, bounds and cancels its actual reads and replay.
`bind_replayed` consumes that exact cursor once only after matching the full selected
Header/state and original live group/source. Refusal preserves the same cursor/model and
preallocated identity. The origin is borrowed, so a refused bind cannot drop its last
payment under a host writer. No snapshot/model adopter or old-token rebinding exists.
Actual App frozen-H capture, new cold ownership and final Current proof are still
unfinished; this mathematical boundary does not establish production restart recovery.

`derive_verified_append` verifies the original founder's signed Append and full result image
once. Its opaque candidate owns that exact next model and tree output. After actual SavedB/
current proof, the private Root adapter supplies `V2HostSelectionExpectation` independently
from its real receipt. All original identity/parent/origin/selected Header/state checks run
before taking the candidate Option. Refusal preserves the same owner. Successful advance
returns actual old-model/output debt for destruction outside writers; Root must cache its
advanced phase before drop/refund/callback/fallible return. HOST configuration does not prove
App storage durability or native permission.

Semantic witnesses are constrained to one exact V2 Create/Profile/Admission/tenure. They
check the actual signature, full subject, realm and V2 Grant/Basis. They cannot grant a reply,
Edit, Delete, Join, moderation or another Create. Historical semantic evidence stays additive
when the source closes. Acceptance separately checks the record/action, exact context,
ordinal and inclusion under the COMPLETE authenticated current `(context,count,root)` tip.
Only the SAME original group/channel owner can receive Proven support. A/I/S and unselected
candidates issue nothing. Proof refresh under an advanced tip preserves unchanged effect
identity for the same record/ordinal/context/origin.

Tokens and retained results observe one `V2ProjectionOrigin`: actual cached read/mount/root/
scope/writer/task negatives, without I/O, host locks or strong SDK/Store/sender custody. A false
observation latches permanently. Publication checks before and inside actual original group/
view readers. Equal labels or newer sources cannot renew old results. Cancel is not drain:
an already admitted callback may finish; actual host close must join the original group
completion before acknowledging closure. Root pays origin/observer and escaping weak tails.

Sync plans and verifies outside global writers. A paid weak exact-plan observation does not
borrow the whole mutable preparation. Under real Current/selected-I/Stop/close admission,
`sign_reserved_append_bytes_data` checks original identity and signs only its stored bounded
canonical preimage, caching raw64 immediately before any later hook/negative. Header
materialization uses that same raw signature outside writers, then Core derives one candidate.
Both Append and complete Create can consume existing inert DATA after a late negative. No
Node/key/source/signer/exporter/Clock/RNG callback or reseal occurs during extraction. Missing
output returns the same preparation; Create caches its packet identity before the late edge.
The actual Root host retains the SAME independently paid Create/Append resources through all
detached and residual tails before any effects. This payment composition is still being built.
